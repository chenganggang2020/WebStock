# 024 跨文稿作者与主题证据汇总

两端0.24继续使用Qt控件与Java Views，不改变看盘三布局、内部子页面、采集队列所有权、原稿或生产库。汇总为本机只读投影，不调用AI，不把多个观点升级为事实。

## 身份与版本

- 新分析快照新增可选 `sourceIdentity {authorKey,workKey}`，原有五项 `sourceSnapshot` 契约不变。规范抖音来源主页优先；旧文稿使用已导入的 `legacyOriginal.channel_id`；身份未知按文稿根ID隔离，不能按同名作者归并。显示名可作为别名，不能作为身份依据。
- 同一作品的来源修订按根ID归组。存在来源采集元数据时，先校验标题/说明指纹和采集时间，再选最后实际观察版本；内容回到早期版本时不能按最初创建时间选错。缺失/冲突时间、损坏指纹整组标未准入，不随意挑一版。
- 最新版本质量不合格不回退到旧版关系。旧版保留在全部文稿列表并明确标记。无分析、有效零关系分析、未准入、来源旧版分别统计。
- 当前正文哈希、连续引文、两个实体和来源快照均重新校验。旧分析缺稳定来源身份仍可在单文稿历史中阅读，但不自动混入作者汇总；没有原始证据的文稿不能补造关系。

## 原生操作

研究页内增加“跨文稿汇总”（安卓“作者汇总”）。作者筛选决定作品范围，主题只筛选引文，不隐藏该作者未准入文稿。列表100条稳定分页，显示全量计数；每条引文保留文稿ID、分析ID、正文哈希及来源快照。点击打开指定只读历史并定位连续引文，未保存的关系草稿先拦截并在当前页显示原因。

计算放在后台，刷新前清空旧结果，快速筛选丢弃旧任务，销毁后不回写控件。安卓状态包只保存筛选键/模式/页码，不放全量正文；避免Spinner晚到事件把恢复的第二页改成第一页。安卓横屏采用左侧可滚动筛选、右侧结果和分页，触控高度仍48dp；竖屏维持顶部筛选、下方列表。

## 验证与已修复问题

测试先暴露并修正：未知作者更新被拆成两个作品、内容回到初版时选错最新版本、未知作者改名被自动重归属、Android晚到选择事件重置页码、汇总草稿错误不可见、横屏控件挤没结果区。真实旧资料操作另暴露Qt读取空JSON时插入null，导致“未分析”误当已有分析并显示空原文；改用只读value访问并加独立回归。新增单位测试最初的文稿不足30字，不满足既有质量规则；修正测试材料并显式断言准入，未降低业务门槛。

深色截图还暴露共用业务按钮浅背景/浅字问题；只对BusinessScreen按钮按启用/禁用状态设置主题前景与背景，并为Spinner箭头和Android30+系统栏设置相应色调，不影响报价语义颜色。列表检查支持共用主题的浅色文字，而不硬认定一个与应用主题不一致的色值。

985份既有只读旧导出在两端本机隔离库计算均为151待分析、834未准入、0已分析；完整分页和原文打开不代表这些资料已生成研究结论。既有受控101条关系用于验证第二页、支持/相反观点、原文定位、重建、取消和主题筛选，不冒充真实研究。

最终构建、回归、截图、安装签名和包哈希以 `output/native-ui-design-20261010/native-v24/acceptance.json` 为准。官方在线来源/CDN、自动AI分析、旧图文件迁移、长期运行和ARM真机仍独立待验；117项不因本段升级为全迁移完成。
