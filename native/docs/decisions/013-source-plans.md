# ADR 013：持久作者计划与来源运行历史

日期：2026-10-12。用户授权持续迁移，不逐批重复审批。本阶段不代表全链路或117项全部完成。

## 实现

Qt“采集”新增“作者计划 / 运行历史”内部子页。最多50作者，主页规范化为稳定ID；保存、启用、单次运行、恢复全局调度、停止分离。每轮1–50条，间隔10–1440分钟，来源串行执行，不补跑漏掉的所有周期。复用SourcePage和既有下载→识别→研究队列，不复制提取器。

原生业务库旁的`.sources.sqlite`保存计划和不可变运行快照，不改旧数据库和BusinessStore备份格式。QLockFile单实例所有权；SQLite BEGIN IMMEDIATE和唯一在途索引约束。崩溃遗留running在下次打开标interrupted；来源全局调度启动暂停，用户主动恢复。计划库损坏/锁冲突只禁用计划页，不影响其它原生业务。

来源调度暂停不代表已获本机批准的下游任务均暂停。下游保留0.10的独立恢复规则。完成历史显示来源阶段及“已加载/处理/排队”；不能将queued写成下载、转写或研究成功。界面最近200轮，更早记录仍存库，分页/导出与计划库备份未加入。

## 停止契约与修复

- 停用先停止当前执行，再保存计划状态；保存失败也停止，错误留在页面。运行结果保存失败暂停调度，记录待核对，不能把内存结束当磁盘提交。
- 来源完成后保留当前轮停止票据，仍可取消尚在下载/识别的下游；不把已经完成的来源历史改成取消。
- 新来源轮次清旧票据/计数，旧票据不会停止新轮；参数校验失败也不继承上一轮计数。
- 每个下游句柄绑定id和executionRevision。只停止其拥有的在途版本，恢复后的同ID替换记录不取消/改写。CollectionPipeline/CollectionRunner的可选修订参数兼容原任务页直接停止。
- 在途停止先按内存所有权取消网络/进程，再写状态；数据库不可写不妨碍实际停止。无法保存则暂停调度，不进行零延迟无限重试。

## 验证及边界

`output/native-ui-design-20261010/native-v13`保存规格红绿测试、最终全回归及交付清单。计划库/控件测试使用临时库和假来源，下载停止使用可控QNetworkReply，ASR停止使用测试专用子进程；没有以夹具冒充真实平台成功。

两项P1红测（计划写入失败仍在采集、来源结束后不能停下载）及同ID恢复替换P2红测均保存，并修复后复测。新增旧票据不误停新轮、失败计数清零和有修订绑定的写盘失败停止测试。最终套件结果以`ctest-final.txt`为准。

真实平台会话仍需用户本人登录/处理验证码；v12实际公开页19条并非已登录。真实CDN下载整链、Windows可视会话验收、Android同等计划/长任务和ARM真机未完成；本阶段未重试资金端点，最近旧Axios/Qt检查仍断连。没有改代理、TLS、生产库、签名或远端。

QLockFile依据：[Qt官方文档](https://doc.qt.io/qt-6/qlockfile.html)。使用长持有锁的staleLockTime=0和非阻塞tryLock；不强行删除另一窗口的锁文件。
