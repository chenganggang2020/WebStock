# 023 采集队列所有权与识别子进程寿命

状态：Windows 0.23 阶段修复；安卓仍0.22。本段不改变三布局、内部子页、下载来源、研究规则或生产库。后续跨文稿聚合按 CONTINUATION-PLAN-v23.md 推进。

## 问题与决定

此前每个 CollectionRunner 构造都会把 running/queued 改为 interrupted，Pipeline 也会恢复在途阶段。第二窗口可能误恢复另一个正在工作的窗口。现在按规范数据库文件路径持有同一个 QLockFile，取得所有权之后才恢复。媒体目录不同不能绕过；存活进程不按超时强制抢锁。Runner、Pipeline 的入队、取消及来源操作均在业务边界检查。

未取得锁的页面继续可读，但执行、编辑、引擎配置和来源会话操作禁用。关闭原拥有者后，用户可在原生内部页主动重试接管；定时 tick 不偷偷接管。只读页面不打开作者计划库，避免先抢计划锁阻止拥有者使用；接管成功后再打开，失败可就地重试。只恢复本机已明确批准的任务，导入备份不携带执行许可。

审查发现仅保护数据库仍不足：所属窗口崩溃后，Python 识别可能继续运行。Windows 使用非继承 Job 句柄和 KILL_ON_JOB_CLOSE，并以 STARTUPINFOEX 的 JOB_LIST 在创建进程时原子加入。保留 Qt 的标准输入输出配置，失败不降级到无保护运行。正常结束/取消释放当前 Job，崩溃由系统关闭句柄；子进程结束和析构写盘之前队列锁不会先释放。此机制要求 Windows 10+，不更改安卓服务行为。

## 证据与边界

- 真测试子进程复现第二窗口错误恢复、竞争计划库，以及父进程退出后识别子进程残留；均先失败后修复。
- 最终27组 Qt 回归全部通过，包括正常退出/崩溃接管、同一路径别名、未批准任务不执行、只读编辑、无模态窗口和来源会话拦截。
- 已有本机视频实际运行模型，29段识别→自动入研究库→不覆盖人工研究修改→校对保存与重开通过，106.6秒。测试库、测试设置独立；第一次实际测试因测试应用未初始化独立设置而未启动，不算业务成功，修正测试后保留成功与失败日志。
- 安卓0.22在 emulator-5564 的6模式756检查通过；不是新APK，也不是ARM真机结论。
- 旧v9/v10/v22等没有采用此锁协议，不会被新锁自动阻挡；不强制关闭用户旧窗口。官方平台/CDN、长时间运行和实时资金稳定性独立待验。117条仍未全部完成。
