## 已核实的起点

- 旧 `services/creatorIndustryService.js` 按 `expert_channels.id` 读取作者作品，而不是按显示名合并；每次读取重新校验文稿质量、正文哈希与 `creator-industry-graph/v2`，不把历史分析自动画入当前图。
- 当前 Qt `creator_page.cpp` 与 Java `CreatorPanel.java` 已有单文稿完整关系列表、局部关系图、连续引文、原文高亮、人工修订和历史只读快照，不能重写或丢弃。
- `creator_analysis.hpp` / `CreatorAnalysis.java` 的来源快照保留 id/title/channel/publishedAt/sourceUrl，暂没有稳定作者身份。`source_capture.hpp` 已在作品上保留规范 `sourceProfile`；只读旧导入 `legacyOriginal.channel_id` 保留旧作者ID。仅有同名 `channel` 的手工资料不能当作同一个作者。
- 来源更新另存 `sourceRootId` / `sourceFingerprint` / `sourceRevisionAt`，原作品与更新版本并存。聚合须公开版本数量，不把同作品多个版本当作多份独立证据，也不静默删除历史。

## 实现合同

1. 先增加纯 C++ / Java 聚合模型及失败测试，再接已有原生子页。只读聚合不修改正文、分析历史或生产数据库。
2. 稳定作者键优先规范来源主页，旧资料按旧系统作者ID单列；未知身份按文稿隔离。不同来源和同名作者不自动归并。若需跨来源合并，另走显式映射，不推断。
3. 新分析快照可增可选作者身份；旧快照仍可读。旧快照缺身份或来源元数据与当前记录冲突时标明限制，不用当前来源冒充当时来源。
4. 作者与主题筛选显示总文稿、合格文稿、当前分析、待分析、质检拦截、无关系、历史版本数量。空关系的有效分析是已处理，不等于未处理。
5. 汇总中每一条关系保留文稿ID、分析ID、正文哈希、引用与来源快照；支持/相反观点分别展示，不通过票数升级为事实或推断证券代码。聚合图允许局部显示，但列表完整性与截断边界必须可见。
6. 点击关系跳到同一子页内的指定文稿/版本/引文，保存未完成草稿的保护仍生效。返回规则、桌面三布局、安卓独立本机运行不改变。
7. 大文稿集合在后台读取/筛选，快速切换丢弃旧结果；安卓重建保存小型选择身份，不把全量正文塞入状态包。

## 验证顺序

- 先测同名异ID、改名同ID、未知身份、质量降级、正文改版、空分析、支持与反对并存、来源更新重复计数、历史快照来源冲突。
- 与旧模型对照总数/合格数/当前关系，不把旧系统 AI 调用或已保存文件当作本轮真实验证。
- Qt 原生控件点击与安卓模拟器操作：作者/主题切换、点引文、草稿拦截、重建、横竖屏、深浅主题，查看真实渲染截图。
- 用只读真实旧资料核对迁入、排除原因和引用位置；数据不足时明确记录，不编造产业关系。
- 既有采集→下载→ASR→研究入库持续回归；官方登录/CDN与长时间运行仍独立验收，不能用本机受控样本替代。
