## 1. 目标与边界

目标不是让数据减少，而是让“点击菜单、查看资料、切换标的”不再等待数据库、整库校验、隐藏页面重绘。数据加载允许有耗时，期间界面必须能继续操作；显示旧结果时保留真实时间，不能假装已经更新或保存。

本轮默认 Windows Qt 主程序优先，保留 C++17、现有 Qt 6 工具链、SQLite、原数据库分域和原生页面。Android 未做对应构建、设备验证前，不延伸宣称手机也已改善。

- 始终保留：原数据、旧库快照、媒体、人工稿、ID、原始时刻、缺值、完整历史、恢复回执、CAS 和保存失败保护。
- 不做：删除历史、将数据截成一年、把未知值补零、减弱完整性校验、降低落盘安全、自动启动旧任务、恢复暂缓联网授权项目。
- 另行决定：正式数据库 schema/日志模式迁移、新依赖、服务器或大规模框架重写；不随性能补丁悄悄加入。
- 不强制退出 Stock，不写正式数据库，不触碰已有量化源码改动。用户已正常退出；本批专项通过并备份后才替换程序。

## 3. 商业软件公开设计对比

资料核查日：2026-10-16。只依据产品公开手册/开发接口，不推断闭源产品内部数据库或线程实现；没有把安装另一款商业软件当成解决方案。

| 产品与公开依据 | 可以确认的做法 | Stock 借鉴什么 |
|---|---|---|
| [TradingView Advanced Charts 数据接口](https://www.tradingview.com/charting-library-docs/latest/connecting_data/Datafeed-API/) | 按所需历史范围取数；按证券和周期区分订阅；最新柱更新与历史修订分别处理 | 精确通知、过期请求隔离、窗口化历史读取；不每次报价重载全图 |
| [MetaTrader 5 数据组织](https://www.mql5.com/en/docs/series/timeseries_access) | 原始历史与按周期生成的快速访问序列分层；需要时装入内存，非长期使用的序列释放 | 原历史完整保留，屏幕只持有工作集；读取范围可向前扩展 |
| [Sierra Chart 刷新间隔](https://www.sierrachart.com/index.php?l=doc/GeneralSettings.html#ChartUpdateInterval) | 绘图更新频率可调，与数据存储频率分开；过密绘图可能挤占数据处理 | 合并界面刷新而非丢弃数据；不靠加线程或提高刷新频率解决卡顿 |
| [同花顺数据下载管理](https://www.10jqka.com.cn/ad_mar/man/11-5.htm)、[数据维护说明](https://www.10jqka.com.cn/ad_mar/man/f6-6.htm) | 官方旧版手册描述按数据类别/时间段下载，以及基础周期数据生成其他周期 | 借鉴分类、按需补历史、存储和显示分离；旧手册不证明当前客户端的内部架构 |

具体实现还须遵守：[Qt 模型只能在所属线程更新](https://doc.qt.io/qt-6/qabstractitemmodel.html#thread-safety)、[Qt SQL 连接线程归属](https://doc.qt.io/qt-6/threads-modules.html#threads-and-the-sql-module)。后台只准备数据，控件及模型更新回到 GUI 线程；不把既有连接指针直接传给线程池。

## 4. 路线比较与建议

| 路线 | 优点 | 缺点/风险 | 选择 |
|---|---|---|---|
| A 只补资金页和主题两处 | 改动小，能针对已复现卡点快速验收 | 首开全量读取、写队列仍在，不能称系统性解决 | 作为第一批，不作为终点 |
| B 保留 Qt/SQLite，分离界面、查询、写入；按需投影 | 原数据和功能可沿用，能按页面逐项证明效果，容易回退 | 需要取消/版本/草稿与排队测试 | **推荐，分三批实施** |
| C 合并所有库、换服务器数据库或重写界面 | 可为未来多用户场景重新设计 | 不能自动消除主线程重绘；迁移面、维护成本和数据风险大 | 本轮不采用 |

WAL 不是独立替代路线。[SQLite 文档](https://sqlite.org/wal.html)说明其可提高读写并发，但仍只有一个写者，还涉及 checkpoint、侧文件及多库事务边界。当前 `MarketStore` 明确使用 DELETE/FULL，先把阻塞操作移出 GUI、减少重复工作；不直接改正式库模式。将来只有压测仍证明锁竞争是瓶颈时，才另做版本、备份、恢复、断电和多库事务兼容评估。提高 [busy_timeout](https://sqlite.org/c3ref/busy_timeout.html) 只会延长等待，不会让主线程异步。

## 5. 拟采用的数据与页面流程

```text
进入页面 → 立即显示外壳/已有结果 → 提交有身份和版本的读取请求
                                       ↓
                         有界后台读取 → 校验/整理快照
                                       ↓
              核对当前页面、证券、周期、请求代次 → 小批更新界面

收到行情 → 更新内存中的当次状态 → 按证券/种类合并可见页通知
                   ↓
           有界持久化队列 → 原库事务提交 → 独立更新保存状态
```

### 5.1 数据库不推倒重建

1. 原库仍是唯一业务事实。业务库 `records(kind,id,payload)` 的原 JSON 不重写为显示摘要；完整文稿、原字段、回执照旧保留。行情仍使用现有 snapshots/series/bars；Parquet 和视频仍是外部文件。
2. 列表使用内存中的轻量投影：ID、标题、发表时间、状态等；打开详情才读取选中 ID 的完整正文。列表排序保留真实时间和稳定 ID，不用展示行号作为身份。
3. 先用现有主键精确读取、一次一致快照和后台校验，不先引入持久化索引库。JSON 字段搜索等仍需要扫描时先后台生成投影；性能证据不足不新增 schema。
4. 一份证券目录/主营快照同时提供 stats、directory、profiles，避免一次进入做三遍全库扫描。只允许复用同一验证过的快照；显式重载、数据替换、来源/版本变化必须失效。不能只凭文件大小或 mtime 认定未变，也不能用大文件哈希阻塞 GUI。
5. 初版不改变 `BusinessStore::validateLedgers` 的接受/拒绝语义。先将读、解析及完整校验移到正确线程、减少重复。将来若按受影响域缩减校验，须证明与旧校验对所有受测正常/损坏状态结果一致；不能把未测的历史损坏变为允许保存。

### 5.2 线程、页面与取消

- 每个页面最多一个正在执行的普通读取、一个待替换的最新请求；共享读取并发先取保守上限2，再据压测调整。线程数量上限不等于排队数量上限，两者分别限制。
- 页面隐藏只保存选择、滚动、草稿并标记数据过期，不因报价重建列表。明确运行中的用户任务继续按原契约执行，不能因隐藏而撤销已提交保存。
- 回调携带页面生命周期、请求代次、完整证券ID、周期/日期/筛选。切换后晚到结果不能覆盖新页；对象销毁不能访问悬空指针。关闭页面不在 GUI 中等待工作线程结束。
- 读连接在线程内部创建和关闭，显式只读；不因“查询”初始化库、建表或更改日志模式。一致读取用短事务，读取完即结束，用户阅读期间不持锁。
- 遇写锁有限重试，保留旧快照并允许继续切页；不能将“暂时繁忙”写成“没有数据”。失败有恢复入口，不进行无限高频重试。
- 草稿与读取快照分离：后台刷新不回填正在编辑的文本；人工保存仍校验当前版本并报告真实提交结果。

### 5.3 收数、存储和绘图分开

- 行情通知至少区分证券、数据种类、周期和修订。先只改高频消费者，保留兼容信号，逐个迁移；不同时替换全程序事件架构。
- 可见页的报价/表格刷新初始合并间隔100ms，数据未变不重建；用户点击、取消、保存反馈不受此节流。数值是待测参数，不是抄用某商业软件的统一最佳值。
- 写队列先计数和去除完全相同请求。仅“可替代最新快照”可合并；5秒/30秒采样、历史柱、修订、人工保存及回执不允许借合并丢失。
- 写队列满时限制生产者入队和后续自动请求，界面保持响应，待保存状态真实可见；不能无声丢弃已接纳的数据，也不能把接纳等同提交。
- 先减少同一次保存中重复读历史；再评估小批事务。保留 FULL，批量大小和事务耗时须实测，不能只用更少刷盘次数当成功。
- K线按显示窗口加指标所需历史准备数据，完整历史仍可向前浏览。EMA/MACD 等递推指标需沿用足够历史或已验证的计算状态，不能简单截断历史改变数值。历史修订/复权改变时重算受影响段。
- 固定242个交易时位、午休、缺口、跨市场交易时区和历史锚点保留；性能改造不伪造秒级数据、不将历史换成今天。
