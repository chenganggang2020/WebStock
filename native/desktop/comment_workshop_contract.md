# Local comment workshop contract (v29)

Scope: D21/P024/P025/P026/P027 from commentStrategyModel.js/commentStrategyLab.js and their four native panels. P024 is **comment** evidence, not the separate knowledge EvidenceLibrary. No AI extraction, online creator verification, collection session reads, backtest, parameter completion or order generation.

Input is explicitly user-selected/exported JSON: exportChannels array, `expertChannels` / `data.expertChannels` / `channels`; `{channel,observation,commentData}` saved-response bundle; browser `webstock.commentStrategy.ruleCards` and `webstock.commentStrategy.evidenceLabels` (object/array or JSON-string values); or native `comment-workshop-v1` complete backup. Records preserve full comment text and version bodies, parent/reply identity, author name/platform id/profile, publication/observation times, likes null, visibility, channel/observation/content identities, public source URL, content/transcript, coverage and evidence/availability declarations. Signed query/fragment/userinfo and media/session/local paths are excluded. Maximum JSON/record/backup 25 MiB; reject overlimit rather than slice.

Pure import preview writes no evidence or card records. UI also saves a recoverable preview draft. Explicit merge inserts new records, skips semantically identical records, keeps existing on conflicting same identity, all within one transaction. Observations are immutable source snapshots; changed comments/coverage/body create a new full snapshot ID. Channel + stable observation key + normalized complete payload form that ID, consistent in Java/Qt (tested including Chinese and em dash). Same comment ID under another observation cannot inherit a label/source link. Native backups cannot forge verified creator status without matching profile/verification-method/snapshot-scope. Old max-200 backup omissions and absent parent/comment coverage are not repaired or called complete.

Creator display: profile equality or source platform label only, explicitly an imported snapshot assertion; same-name remains suspected. Coverage stores both declaredComplete and effective complete; pagination/partial totals cannot be called complete. Missing likes/coverage/total remains unknown, actual saved/group counts may be zero.

Manual rule fields: title, universe, timeframe, signalTiming, entryRule, exitRule, stopRule, positionRule, costRule; sourceChannelId/sourceObservationId/sourceCommentId/updatedAt and frozen sourceRef retained. Eight nonempty fields yield `rule_complete_not_validated`, never valid strategy. UI field limits mirror old maxima and refuse saving overlong input, no silent truncation. Shared rule draft and cards use recordRevision optimistic writes; unsaved restored draft blocks card switches. Explicit new/reload are the discard operations. Removing a saved card first stores a full archive in the same transaction; restore refuses same-ID replacement. Archives/paged records/full backups persist across reopen.

Evidence labels are manual support/counter/question/unclassified. Keys bind snapshot + comment ID, never guessed from text/likes/AI. Old unattached references preserve old IDs/keys and report missing; import doesn't invent original comment text. Accurate rule-comment reader revalidates frozen comment snapshot, displays full body/parent/version context. Local native-source binding is explicit, unique same-public-URL and identical-full-body only; opens use v28 exactSource snapshot/revision/body checks plus host's complete-row/draft protection. Missing/ambiguous/restored/edited sources refuse a jump while imported source text stays readable.

Independent SQLite: `comment-workshop-v1.sqlite` Android; `<business-file>.comment-workshop.sqlite` Qt. Version1, application_id 0x43575331, records keyed by kind/id. Only genuine single-column android_metadata is allowed for Android new-file initialization; other tables or incompatible schema fail without rebuild. Android chunked payload reads avoid default CursorWindow size truncation. Native backup includes observations, rules, manual labels, bindings, persistent draft, and recoverable archives; no BusinessStore or production DB schema edits. Whole-software backup integration remains root-owned.


Lifecycle addition: selected-file prepared preview is a private recoverable draft (not approved evidence), excluded from evidence backups. Constructor restores it without merging. Explicit confirmation atomically checks and consumes its revision with the evidence merge. File-picker cancellation keeps existing preview/card edits. Business readers use internal panels; host back APIs preserve main editor/scroll position.
