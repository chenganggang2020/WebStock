# Offline evidence review and candidate approval

Scope is the local review/approval portion of P020/P022, grounded in `js/modules/aiResearch.js` (knowledge evidence/search/analyze/manual handoff/runs/import UI), `services/knowledgeService.js` (rowToSearchResult), `services/gptPickImportService.js` (normalization/Markdown/plain/manual/external/runToItem), and `services/researchRunService.js`. `fixedWorkspace.js` moves the original controls; no separate aiWorkspace.js exists in this checkout. The decision-packet/paper-portfolio flow is separate. Network knowledge retrieval, paid model execution and external automation are not claimed as migrated by this slice.

Existing ResearchRuns provides historical full-run import/read; SourceAnalysis/Handoff provides creator analysis packets and manually returned results. This module reads existing BusinessStore research reports without writing/copying them and accepts their explicitly exported records when the user chooses an independent import. It adds citation review, independent candidate previews/approval and history; it does not edit the existing modules or their schemas.

## Inputs and provenance

Accept direct candidate arrays; candidates/picks/stocks/items/selections JSON; old researchRuns exports and direct old run arrays; native-business-v1 reports; manual pick runToItem records/items; source-handoff-v1 records and old webstock_ai_handoff_results exports; complete evidence-review-v1 backups; legacy Markdown tables and plain code/name/inline reason/risk/analysis material. Full report, prompt, question, evidence blocks and original input objects remain inspectable as plain text. Old pending/failed states remain pending/failed; no model call resumes. The supplied raw text is preserved by the text/Markdown report. Analytical text arrays retain their original arrays and display all string elements without truncation. Malformed JSON/nested old JSON, unsupported record types, missing business fields and oversized records are refused without replacing the previous stage.

Per-file and per-record serialization are bounded to 25 MiB; source files can require more space after normalization, in which case refusal is explicit. At most 1000 candidate rows per report and 10000 imported records, with no silent row truncation or deduplication. The old manual service's 20-row truncation and code-only merge are deliberately replaced with inspectable duplicate rows and explicit selection. Report identity is the canonical original-object SHA256 (the same stable numeric fingerprint convention as ResearchRuns); any original/report/citation field alteration invalidates a native report backup. Changed original reports have distinct IDs. Candidate history validates each original row and full identity against its captured report, plus the complete batch fingerprint; it cannot silently change a reason/name or attach to another report.

## Citation checks

An imported sourceRef carries kind/id/full SourceAnalysis snapshot/bodyHash. Reopening calls exactSource against fresh docs/collections and then passes the full current row to the host; same-ID edits, restore/revision changes and missing records refuse the jump. A legacy sourceId/quote may identify a current knowledge_sources document whose complete text includes the quote, but this is `snippet-only`, never proof of the historical full version. Missing, ambiguous and changed snippets retain their old text and explicit state. Manual binding requires the user to read the current full document, then freezes that exact current version under a separate CAS binding; this explicitly does not establish the historical report's provenance. Each candidate's evidence IDs are checked against its own report; unknown/missing IDs and absent IDs are shown, never inferred. Approval and history reads refresh these checks; they remain independent-verification pending even when the current full snapshot matches.

## Exact securities and explicit actions

The host supplies a current catalogue of `{id:"SH:stock:600000",name:"浦发银行"}` with market/type/six-digit identity. No market or security type is guessed from a six-digit code. The user may enter a complete identity for a code-only legacy candidate. Explicit identity/code/market/type declarations must agree; impossible market/type/code combinations refuse. Catalogue absence, duplicate full identities and exact-name conflict block candidate approval. To resolve an original-name conflict, correct/reimport the material explicitly as a new report; no automatic renaming is performed. Different security types sharing a code remain distinct. Selected duplicate full identities are refused and already approved identities from the same report cannot be repeated.

Manual acknowledgement permits saving an independently unverified research candidate whose citation remains incomplete; it never upgrades reference/fact/strategy validity. Approval rechecks the full selected rows against immutable report rows and a fresh catalogue inside the module transaction. Saving does not call host actions. Only separately clicked `chart` / `watchlist` buttons in approved history request the stable host callback, after another fresh full identity/name check. Root remains responsible for implementing that explicit action; no watchlist, position, upload, login or trading code exists here.

## Persistence, lifecycle and navigation

Independent SQLite application_id `0x45565231`, version 1, records(kind,id,revision,payload), composite key; incompatible/nonempty foreign databases are refused, never rebuilt. Qt path is BusinessStore.filePath()+`.evidence-review.sqlite`; Android uses a root-specified independent absolute File. Reads use bounded full-record retrieval on Android to avoid a small CursorWindow. Lists use 50-record metadata pages. Root BusinessStore is read-only.

Paste input, selected report snapshot, full identity input, manually selected candidate rows and acknowledgement are private CAS drafts. A restored report snapshot remains readable when the current original disappears; it is not represented as a live source. Pending preview is a separate private CAS row. Canceled SAF/file selection does nothing; invalid input preserves the old preview. Explicit cancellation clears only that preview. Confirmation checks and consumes the exact stage revision in the same transaction as merging; stale stages refuse without partial writes. Back and theme changes preserve main controls, draft and scroll position; business readers are internal subpages, with no QDialog/AlertDialog. Root calls the module back API only when this module is active.

Own complete backups contain approved reports/batches/manual bindings and exclude/reject private drafts/previews. Import is explicit preview + keep-existing merge with duplicates/conflicts shown, all-or-none on invalid records. No production stores, account/session state, shared host entry files/build/device, commits or pushes are modified by this slice.

## Host API and acceptance boundary

Qt: `evidenceReviewPage(business,parent,catalogue,action,sourceOpener)` and `evidenceReviewBack(page)`. Add model/store/page .cpp files only. Java: `EvidenceReviewScreen(Context,BusinessStore,File,Instruments,Action,SourceHandoffPanel.Opener)`, `setFileActions(Exporter,Runnable)`, `previewImport(String)`, `setDarkTheme(boolean)`, `back()`. Catalogue and action are optional but approval/actions remain blocked until usable. Constructor restores private lifecycle state; no additional save/restore/close API is needed. Host actions/theme/file actions are reapplied normally by root.

Dedicated checks exercise real isolated SQLite, immutable report/batch identity, stale preview/CAS, atomic consume, independent approval, duplicate/name/type conflicts, complete backups, legacy formats, full/captured/missing/changed citation states, Java/Qt normalized fixture parity, and actual Qt UI input/preview/selection restoration plus internal back. Java instrumented checks additionally provide SQLite and real screen lifecycle/theme/back coverage for root to run. Standalone compile/model/Qt checks do not prove shared application integration or Android device acceptance; those remain root-owned.
Generic old evidence array literals remain full unversioned literal evidence with generated LEGACY-row identities; a string is not guessed to be a source ID. Explicit symbol market prefixes/suffixes and complete six-digit numeric codes are honored; numeric short codes never gain guessed leading zeroes.
Manual bindings also validate captured report/index/composite identity and require the full bound snapshot to contain the exact imported quote. Explicit shared-draft/preview reload provides recovery after a CAS refusal; it only replaces the current editor when that button is deliberately clicked.
