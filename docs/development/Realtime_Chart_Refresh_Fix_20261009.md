# 分时空白、粒度切换与当前标的刷新修复

日期：2026-10-09，北京时间。基线：`38e8bc7caf6613532f3df930b7b8e22050c5b0bd`，维护分支 `codex/runtime-lifecycle-cleanup-20260926`。

## 已核实的原因

1. **隐藏图表尺寸丢失**。真实 Edge 浏览器，使用项目静态隔离服务器和运行版同一只股票的 GET 响应：分时正常显示 → 日线 → 调整窗口 → 分时。隐藏时 `State.timeChart` 被 resize 为 `0×0`；重新显示后 DOM 宽 1154，但图表与 canvas 仍宽 0。数据已返回，状态却显示“曲线已更新”。不是未取到行情，也不是数据库查询空结果。
2. **辅助接口阻塞主刷新**。`loadRealtimeData()` 虽先绘制分钟数据，仍等待报价和竞价的 `Promise.all` 才结束。报价也必须先等分钟接口。可控挂起测试复现三项失败。
3. **个股详情没有进入每秒本地快照轮询**。`LiveRefresh` 原来只覆盖首页、自选、持仓；首页批次未必包含当前非自选股票，且必须等待持仓读取。详情报价随分钟流程更新，后者受慢接口拖累。
4. **重新切回粒度缺少独立缓存恢复**。现在按证券和粒度保存最多 12 个窗口快照，原始日期不修改，空响应不清除已显示的对应曲线。

## 最小变更与限制

- `chartTheme.resizeVisible()`：可见时恢复实际尺寸；不把隐藏容器再次压成零尺寸。复用画布及已有缩放状态。
- `realtimeChart`：分钟主请求完成即放行刷新；盘口和竞价独立应用，仍检查证券、粒度、请求序号和可见性。旧响应不可回写；按真实时间比较报价，支持北京时间与带时区时间戳。
- `liveRefresh`：详情与首页每 1 秒读取既有本地 snapshot 接口；首页每个最多 30 只批次均优先当前标的，其余轮转。后台持仓读取不阻塞盯盘报价，持仓变化仍触发重新估值。
- 继续使用服务器既有每代码请求合并、上游最短 3 秒间隔，不添加强制刷新。5秒/30秒仍是聚合粒度，不是行情源时效保证；公开明细后台补取与本机快照各自保留来源。
- 显示独立的报价源时间、曲线截止时间；源时间未知不冒充最新，请求时间不代替行情时间。盘中报价超过 15 秒显示滞后，收盘行情不误标为盘中故障。
- 未修改采样数据持久化、午休压缩、九转公式、生产数据库、任务调度或外部数据授权。

### 复现与修复

- **HTTP 失败清图**：5秒 → 30秒 → 5秒，模拟最后一次返回 503，安装版仍缓存 2948 点却销毁价格和成交量实例，并同时提示“保留上次曲线”。证券/粒度对应缓存现在先恢复；失败维持图表、原日期和缓存标识。迟到报价可以更新报价，但不得覆盖分钟源的失败提示；失败信息放在状态栏开头。
- **补取被报价阻塞**：安装版先展示本机 2162 点、837 个量能点。挂起独立报价时，4秒后没有第二次明细刷新；解除报价等待后才恢复 2948 点。主请求与辅助请求分离后，报价一直挂起仍在约3341 ms内自动检查补取并重画（不是上游行情延迟指标）。
- **短响应覆盖历史**：同日、同一粒度/时间标签的非空短响应不等于删除历史。按时间键保留已经观测的点，更新重叠价格；缺量保留既有量额和来源，不累计两次，明确的新零量覆盖旧量。次日替换而非拼接；较旧日返回不得把新日缓存回退；1分钟换源和时间标签变化不拼接。
- **边界成交被过滤**：`aggregatePrices` 原来仅接收 `continuous`。现在保留已观察的开盘结果（09:25:00—09:25:05）与收盘时段成交（14:57:00—15:00:05）；不填造竞价过程。边界迟到数秒的记录显示在09:25/15:00边界，原时间保留为 `providerLastAt`。读数显示“成交记录/源时间/非虚拟匹配量”；09:15—09:25的普通报价仍与正式匹配字段分开。
- **点数说明**：标题改用实际绘图有效点数（包括开启的竞价图层），不再用排除竞价后的数目混称已记录点数。获取时间不再称行情“截至”时间。
