### 2.2 已定位的加载机制

1. `routes/market.js:391` 的 `/api/minute`：秒级请求先读本机聚合，再调用公开明细服务，将两份数据按日期、时间合并。
2. `services/publicPriceDetailService.js:268 list()`：冷缓存触发异步 refresh，**不等待补取完成**，先把原有快照/本机记录返回。该设计本身可以减少白屏，但需要明确的部分数据状态。
3. 同文件 `fetchSnapshot():116`：按页顺序请求，每个未缓存页先等80ms；全部页读完后再次核对索引，才返回快照。`refresh():236` 随后完整落盘。**没有按页交付已校验片段、没有页数进度接口**。
4. 全局最多两个补取任务；容量满时，list不入持久等待队列，依赖前端下次轮询重新争取名额。补取失败至少等待60秒再试。属于可造成进一步等待的代码路径，**不是已证实截图当刻就发生了拥塞/失败**。
5. `js/modules/realtimeChart.js:192`：loading/busy期间3秒后重读，否则按常规频率；`loadRealtimeData():377` 可接受新快照。图标题只说“已显示86点”，补取状态放在长状态行尾部；有本地点时busy没有明确的排队文案。用户容易把当前部分记录当成“已经加载完的整日数据”。

**直接结论：截图确实显示了稀疏本地采样。已复现的体验缺陷是“先展示稀疏记录＋整批补取才发布＋进度/完整性表达不清”。没有证据证明这张图是数据库查询慢，或前端拿到476点后删成86点。**

历史边界：没有保存截图瞬间的请求起止与backfillState，不能唯一还原当时处于正常loading、排队还是失败重试。既有日志也不足以逐个解释当天12段本地记录之间为什么停采；当前收盘后采样状态不能代替盘中历史状态。

## 4. 最新安卓的实际差距

### 4.1 两项新复现，而非主观观感

**P0：首页指数是死入口。** Android230/web/app.js:79 `dashboard()` 渲染 `section[data-index]`；click委托在:199只接受最近的button，未处理data-index。浏览器点击上证卡后仍为dashboard，新增K线/分时请求为0。

只把卡片改成股票按钮仍不够：`openStock():185`只接受六位代码；`symbol()`会将000001推断为sz股票。必须携带 `market + type + code`，否则上证指数会被误开成平安银行。Java `StandaloneCore.symbol()`虽支持sh前缀，前端入口还不支持完整标的身份。

**P0：跨页返回会回错股票。** `navigate():40`只压入`{view,scroll}`；`WebStockPhoneBack():41`恢复页面，股票等仍是全局变量。实测：平安银行→研究→搜索万科A→返回研究→再返回股票，结果仍显示万科A，未恢复平安银行。

### 4.2 已有能力要保留，不重复造轮子

本轮 Android230 Node 40/40、现有图表浏览器夹具15/15通过。已验证的夹具行为包括缓存先显示、慢最近浏览保存不挡开图、旧响应不覆盖新选择、刷新保留图表实例/缩放、离线保留数据、补载历史、上一只/下一只保留来源顺序、九转说明弹层、360/430/844宽度布局。

因此不能说“安卓没有缓存”“每次行情刷新都销毁图表”或“完全不能返回”。问题在完整的跨入口状态、品种覆盖、可达性及缺失业务。

### 4.3 其他源码确认的不足

- **信息层级**：底部行情/自选/资金/研究/全部，另有同组横向页签；股票详情固定归入行情，即使来自自选。持仓/账本/统计藏在自选组，“资金”却主要是公开排行。用户的“持仓资金”和“市场资金”容易混淆。
- **图表操作层级**：全局头、报价卡、上一只/下一只、图表标题、周期条、指标选择、约104px读数区先后堆叠，普通竖屏图表被挤到较低位置。需要折叠报价细节、减重复标题、首屏优先展示可操作图表，不删除必要数据口径。
- **刷新频率**：`refreshDelay():157`通常盘中15秒检查报价、非交易时段300秒；`refreshVisible():159`图表读取还受60秒门槛约束。不是手机秒级推送。`marketHours()`仅按工作日与时钟判断，并非完整交易日历。
- **数据与页面生命周期**：`render():51`重建整页并销毁图表；正常行情刷新已走局部patch，不应回退。周期按钮、跨页返回、部分账户与榜单刷新仍走重建。`PhoneCharts.draw():64`仍全量setOption，即使内容没变也未统一跳过。
- **历史视野**：PhoneCharts已按时间恢复“向前补历史”的视野；尾部新增数据、跨导航恢复和退出重开仍需补专项验证，不能凭已有测试推定全部通过。
- **原生请求取消**：JS有序列号保护，可忽略旧响应；MainActivity仍把网络请求投入3线程池。JS超时/退出当前页不等于原生在途连接停止，占槽等待需要单独测量和取消协议。
- **手势**：图区域使用touch-action:none与ECharts默认手势；不能据此宣称物理手机纵向滚动、捏合、长按与系统边缘返回已协调。须定义手势优先级并真机验收。
- **文案不一致**：`pendingFeatures`仍把“九转历史回看/VWAP”等组合写成未迁移，而当前图上已具有部分信号解释及分时均价。应由细分能力表生成状态，不用笼统的旧“待迁移”描述。

## 5. 推荐目标体验

保留原生宿主＋本地存储＋现有图表能力，不为“像网页”立即换框架。先建立以用户任务为中心的移动导航。

- 底部建议：**自选 / 市场 / 研究 / 账户 / 我的**。市场资金归“市场”，真实账户资金归“账户”；收藏的快速入口可放首页。默认打开自选或上次选择的首页。
- 顶层切换不不断堆网页历史；每个顶层保留自己的列表滚动、筛选和选中项。
- 个股详情是可返回来源的统一页面，按“紧凑报价 → 分时/周期 → 固定读数 → 主图/量能/副图 → 公司/资金/资讯/研究”组织。更多设置用底部面板，不长期挤占图表。
- 标的身份至少为`{market, assetType, code}`；页面上下文保存来源列表、顺序、筛选、排序、标的、周期、复权、指标、可见时间范围、选中时间及跟随最新开关。
- 图上横向拖动看历史、双指缩放、长按读数、点标记看解释；在非图区域滚动页面。全屏/横屏保持同一图表状态，不再造一套页面。安卓系统返回优先关弹层，再退全屏，再回来源。
- “报价截至”“曲线截至”“后台正在补取”“历史缓存”分开显示；刷新成功但行情时间未前进时不能说已更新到当前。
- 未完成能力集中在能力说明；常用入口不能伪装成可操作的空白页面，也不能把待授权数据装作普通网络错误。
