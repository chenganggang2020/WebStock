# 后台采集、增量更新与视频资料库：核查及规格草案

日期：2026-09-08。状态：用户已批准修改；核心源码已实现，发布及实机验收未完成。下文保留原核查与目标，实际交付边界见同目录 Collection_Implementation_Status_20260908.md。

## 目标与假设

用户无需保持 WebStock 主窗口在前台，即可持续检查关注作者的新作品、采集和转写；可针对单视频操作，播放已保存的视频，持续积累评论，并更清楚地看到同花顺持仓是否真正更新。

- 默认采用当前 Windows 登录用户下的托盘后台进程，不改为交互式 Windows 系统服务。
- 增加可开关的“登录 Windows 后后台启动”。便携版使用稳定的外层 EXE 路径，不注册临时解压目录；移动文件后提示修复路径。
- 关闭窗口与完全退出区别明确：关闭窗口继续采集，完全退出停止。休眠、关机、退出 Windows 登录后不承诺采集；恢复后续跑，不积压并发补发。
- 新作品继续自动完成详情、归档和转写，不能退回“只检查、等待手动处理”。历史补采独立控制。
- 不接入真实下单，不读取交易密码，不绕过登录、验证码或平台访问限制。

## 本次核查证据

### 运行实例与源码分开

只读检查时，3000 端口由 PID 33480 占用，来自 `dist/portable/WebStock-Simulation-20260907.exe` 的运行实例。当前工作区未重新打包，源码中的机制不能直接当作这个实例全部行为的验收结果。

源码 `electron/backgroundMode.js` 已有关闭窗口隐藏到托盘、显式完全退出机制；`electron/main.js` 启动后台调度。`electron/douyinAutoSync.js` 的自动采集窗隐藏且设置 `backgroundThrottling: false`。没有发现现成的登录自启注册/配置入口。安装包形式本身不等于自启能力。

### 历史视频反复访问：已有运行证据及可复现缺陷

只读生产库 `dist/portable/WebStockData/webstock.db`：

- 模型先生任务开启，间隔 10 分钟。
- 2026-09-08 北京时间 08:52:35–08:57:23 的定时任务，候选 8 条，详情成功 7 条、失败 1 条，新增 0 条、转写尝试 0 条。
- 相邻两轮重复访问了两条已完成转写、发布日期为 2023 年及 2024 年的作品。
- 核查时有 397 条观察记录，367 条非空逐字稿、374 条带本地媒体路径、1814 条评论记录。路径非空不是媒体文件完整或可播放的证明。

源码原因：

1. `electron/douyinAutoSync.js` 将主页作品与本地历史作品合并规划；`services/douyinSyncPlanningService.js` 默认每轮最多 8 个详情候选，详情复查 TTL 为 6 小时，历史缺详情/缺转写也会进入候选。它不是严格的“只更新新作品”。
2. `services/douyinSyncStateService.js:409` 直接把 SQLite `updated_at` 交给规划器。该字段由 `CURRENT_TIMESTAMP` 生成，是无时区后缀的 UTC 文本；规划器 `new Date(raw)` 在本机按东八区解释。
3. 本机只读复现：`2026-09-08 00:57:23` 被解析为 `2026-09-07T16:57:23.000Z`，比正确 UTC 早 8 小时，刚完成的详情会误超 6 小时 TTL。失败退避同样受此时间口径影响。
4. `index.html:1905` 仍写自动只读检查、不打开详情，与实际定时流水线不符。
5. 隔离测试库走真实 `getPlanningState → planDetailCandidates`：刚保存的 `complete/complete` 记录即被判 `stale`；仅在内存对照中纠正 UTC 后候选数为 0。此外，详情成功但转写失败的记录返回 `failureCount: 0`，转写阶段失败退避没有独立接通。

### 资料库与持仓缺口

- 已有 `mediaMetadata.coverUrl` 展示，但主页发现阶段未采封面，详情只尝试 `og:image`；缺本地缓存与加载失败回退。本次生产记录检查该封面字段为空。
- 视频详情没有接入播放器；已有播放器 URL 辅助函数未调用，也没有受控本地媒体播放路由。
- 有底层单作品归档/转写能力，没有完整的单视频任务 API、IPC 与按钮。
- 评论缺席不会自动删除本地记录；但相同评论 ID 更新会覆盖旧文本，不保留修改版本。默认只返回最早 200 条，无分页，后续评论可能看不到。
- 隔离复现还发现旧评论响应可以覆盖新值；导出库存 252 条评论时只带出 200 条。永久留存必须同时修复时序更新、分页与全量导出/恢复，不能仅保证界面上不删除。
- 后端支持多个作者，新增表单藏在通用研究库，采集页没有直接入口。默认作者键包含名称，同名不同账号需防误覆盖；新作者任务需立即注册。
- 同花顺持仓调度源码默认 15 秒检查，最低 5 秒，有并发防重；窗口识别失败才尝试新鲜导出文件。提高计时频率不能解决窗口不可读、未登录或没有新文件的问题。实际持仓数量、行情估值与界面刷新必须分别记录时间。
- `js/modules/liveRefresh.js` 的 `refreshView` 对持仓页提前返回行情快照刷新，后面的 `Portfolio.refreshLivePortfolio` 分支不可达；行情刷新只更新 `State.positions` 已有股票的价格。后台即使同步新数量、新股票或现金，页面仍可能保留旧持仓结构，需重新进入或手动刷新才加载。这是独立于 OCR 成败的明确前端断点。

## 拟定功能与验收标准

### 1. 后台运行状态可见、可控

- 设置页提供后台运行、自启开关与真实状态；托盘可打开主界面、暂停采集、完全退出。
- 启动项保存后读回校验；失败明确提示。关闭/隐藏主窗口后仍能完成离线模拟任务；正常采集不抢焦点，登录失效时暂停相关作者并提示。
- 重复启动不产生第二套调度或并行写库；退出等待/取消正在执行的任务，留下可恢复状态。

### 2. 严格区分增量、补采、重试与评论刷新

- 修复 UTC 解析，覆盖东八区、UTC、已有 ISO 时间和失败退避测试。
- 默认增量只处理新发现的新作品和明确内容变化；点赞/评论计数变化不能触发重复音视频下载、重复转写。
- 已知历史作品不因缺详情被当成新发布作品。历史补采有独立开关、范围、预算及暂停操作；默认不遍历整个历史库。
- 新作品失败进入有上限、带退避的独立重试队列；不阻塞其他作者。有效 `no_speech` 结果不能无限自动重试，人工仍可指定重试。
- 评论/互动刷新有独立策略和时间。确实需要打开旧作品时，界面显示“更新评论”或“历史补采”，不能伪称新作品。
- 无新作品、无到期重试且未启用历史/评论任务的连续两轮，不应访问任何旧视频详情。

### 3. 单视频操作

- 每条视频提供“补采详情”“下载/补存视频”“重新转写”“更新评论并保存”。按当前阶段显示可用按钮、完成时间和失败原因。
- 任务仅针对所选作者和作品；排队可见、重复点击幂等。重新转写优先使用已验证的本地媒体，不先扫描作者主页。
- 自动失败不覆盖原有成功转写和视频；人工覆盖也保留可追溯的历史结果。

### 4. 封面与真实播放

- 主页/详情采集真实封面并本地缓存；必要时使用本地视频截帧，明确标注来源；无图显示占位及原因，不伪造封面。
- 点击进入视频详情，优先播放本地文件，支持拖动进度；未归档或格式不支持时说明原因并提供原始来源链接。
- 媒体按观察记录 ID 授权查询，校验归档根目录、真实路径和文件类型，支持 Range/206。不接受用户传任意路径，不公开整个媒体目录，保留现有移动端访问限制。

### 5. 评论永久累积

- 更新评论即增量持久化，保存首次/最后观察时间、作者回复标识和采集覆盖范围；空快照、失败、远端不可见都不删除本地记录。
- 同 ID 文本或相关字段变化保留版本历史；新增版本表需纳入备份/恢复契约。既有评论仅可作为迁移时基线，不能还原此前已被覆盖的内容。
- 本地分页、总数、搜索与历史版本可查；未抓到不等于远端已删除，不承诺完整抓取所有评论。
- 旧响应不得覆盖新的当前版本；缺平台评论 ID 时使用稳定回退键并标明可信度，不能依赖当前列表序号。全量导出/恢复不得受界面分页条数限制，超过 200 条的评论和历史版本需往返验证。
- “停用作者”只停任务，不删资料。物理清理属于独立明确授权操作，本轮不增加自动删除机制。

### 6. 可视化多作者管理

- 采集任务页直接添加作者：名称、主页地址、同步开关；规范化平台身份防重，同名不同账号不互相覆盖。
- 保存后立即注册任务，不要求重启；支持切换、编辑、停用及查看各作者任务状态。
- 全局串行/有界并发、公平排队；一个作者登录失效或采集失败不阻塞全部。

### 7. 持仓及时性

- 区分“最后检查”“最近成功读取持仓”“持仓源时间”“行情时间”，数据未变化不伪造新快照。
- 保留默认 15 秒检查与并发防重，提供单次立即读取入口；在能够读取的源上更新后及时通知页面，不反复闪切状态。
- 将账户/持仓快照刷新与高频行情刷新分离，通过只读快照版本或变更通知更新持仓数量、新增/移除股票、现金及汇总；不把每秒行情刷新改成每秒 OCR 或写入式账户重算。
- 源不可读时明确缺窗口、页面不适配、旧导出或校验失败；保留上次有效数据且标记过期，绝不把识别失败当空仓。
- 不自动点击同花顺买卖、切换账户、解锁或切换交易页面。不承诺任意最小化/锁屏状态下都可取得持仓。

## 工程约定与验证

沿用 Electron + Express + CommonJS + SQLite，前端现有模块结构，不引入新框架。示例约定：

```js
function timestamp(value) {
  const parsed = new Date(String(value || '')).getTime();
  return Number.isFinite(parsed) ? parsed : 0;
}
```

上面是当前命名/格式示例，不是正确处理 SQLite UTC 的实现；修复时要在已知数据边界显式规范化时区，不把全部未知时间字符串都强行当 UTC。

主要目录：`electron/` 生命周期与会话；`services/` 调度和持久化；`db/` 迁移；`routes/` 本地 API；`js/modules/expertTracker.js` 资料库界面；`test/` Node/前端测试；`docs/development/` 规格与验收记录。

边界：始终保留现有工作区与资料；数据库只做可回滚、经备份验证的增量迁移。自启注册、评论版本表及备份格式调整纳入本规格确认范围。任何云端迁移、真实交易、清库或登录绕过不在范围内。
