## 范围与原因

仅修复产业链差异审计中的 P0：已经分析的文稿被重新标为待复核后，默认图谱仍继续展示旧关系。此前导入/分析路径使用质量门禁，但读取图谱路径只检查正文哈希，并允许旧规范结果回退进入图谱，导致质检状态和绘图不一致。

## 行为

- 默认 `relations` 只包含正文哈希一致、提取规范为 V2、当前文稿质量门禁通过的分析。
- ASR 待复核、图文 OCR 未完成、正文改变或旧规范结果不能继续作为当前关系。
- 读取时重新判断，不写回或删除历史文件，不自动重跑 AI。相同正文恢复合格后，可重新展示已保存的 V2 关系。
- 通过文稿质量检查仍是 `author_claim`（作者观点），不代表公司业务/供货事实已经独立核验。
- 合格分析可以包含零条产业关系：计入当前合格作品，不伪造图谱节点或边。

## 读取接口计数

`GET /api/industry-chain/creators/:id` 添加字段；不改变既有两个计数字段的含义。

| 字段 | 含义 |
|---|---|
| `readyCount`（原有） | 当前正文至少 30 字的作品数，并非质量合格数 |
| `analyzedCount`（原有） | 当前正文哈希有保存分析的作品数，可能是旧规则或待复核 |
| `eligibleCount` | 当前文稿质量门禁通过的作品数 |
| `currentAnalyzedCount` | 当前正文、V2 规范和质量门禁全部符合的已分析作品数，包括无关系结果 |
| `historicalAnalyzedCount` | 当前作者作品集合中曾有分析记录的作品数，按作品去重；同作品多个哈希/规范版本只算一篇 |
| `reviewQueue[].relationCount`（原有） | 当前正文对应留存分析的关系数，不保证可以进入当前图谱 |
| `reviewQueue[].currentRelationCount` | 当前可进入图谱的关系数 |
| `documents[].currentEligible` / `exclusionReason` | 留存分析现在是否符合准入；不符合时给出质量门禁原因或 `legacy` |

历史证据保留在原分析文件中；本轮未新增历史版本浏览器。正文变化后，旧结果退出当前正文投影但仍存档。作品从当前主证据集合退出后不计入本接口的作品计数，不删除其历史。

界面区分“历史已分析 / 当前合格 / 已有正文 / 质检准入”。空图不再写成“尚无已分析关系”，质检表区分当前入图关系和当前正文留存关系。接口未提供的新增计数显示“未提供”，不能用历史分析数冒充当前合格数。
