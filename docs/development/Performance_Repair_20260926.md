1. 高频历史最新记录：取消需要临时排序的查询，复用已有索引。5秒/30秒跨日、竞价、午休与重启结果一致；EXPLAIN不再使用临时排序。
2. 数据库写入：板块龙头批量事务；同批行情的5秒、30秒、快照一次外层提交，失败回滚后内存状态必须可重试。使用内存数据库验证原子性和历史保留。
3. 诊断负担：记录完整事务（包括提交/回滚），避免批量SQL逐条堆栈与IPC洪峰。保持独立观察器识别未响应、异常结束闭合、事务调用约定不变。
4. 明暗盘：同查询缓存优先、后台单飞更新，强制刷新保留明确语义；拒绝跨日期误用，失败不清空旧记录。验证过期缓存、并发、失败及界面更新状态。

## 验证结果

已完成数据库分片及独立交叉审查：

- 5秒/30秒最新记录使用已有 `(code, bar_time)` 主键索引，不再临时排序；没有新增索引或执行生产迁移。
- 板块龙头一批一次事务，同批行情的5秒/30秒/快照三个子写入一次外层提交。
- 原生 COMMIT 外键失败（回调已成功）与普通写入失败都覆盖回滚及重试。两个采样服务的内存水位会重置，历史保留，同一报价可重试。
- 诊断覆盖完整事务边界、同步异常和嵌套事务；事务内部不再逐行生成堆栈并发送IPC。真实SQLite验证各事务变体和异步回调拒绝约束。
- 最终30个文件合并回归 **199项通过，0失败、0跳过**（约8秒），包含行情/量能/补采、数据库事务、明暗盘及产业链隔离基线测试。9个变更的生产JavaScript文件语法检查通过；不是全项目全量测试或打包验收。

缓存分片及交叉审查完成：

- 同日期缓存先返回，保留真实采集时间、旧数据与资金变化对比；后台单飞更新，不增加并行整市场扫描。
- 个股和双向榜跟进同一后台结果；可见时5秒跟进最多1分钟，之后60秒收尾；隐藏或离开停止，休市恢复不会永远停在“后台更新中”。
- 手动刷新透传到真实扫描；跨日期扫描占用时明确失败，不将旧缓存伪报成刷新成功。
- 交叉审查发现的休市隐藏、榜单未跟进、跨日期强制刷新假成功三项边界均已复现、修复并回归。独立复核33项通过。
