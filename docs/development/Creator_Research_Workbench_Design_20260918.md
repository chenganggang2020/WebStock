## 1. 目标与主要判断

把“采集任务”从面向处理流程的页面，改成面向阅读研究的工作台。用户最常见的路径应该是：选择作者或主题 → 找到新视频 → 看内容和证据 → 按需补采或修复；而不是先阅读大量任务设置。

当前并非只能采集一位作者。代码已有“添加作者”、作者级自动检查、单视频补采、转写和评论操作。主要缺口是入口不明显、多作者管理不集中、跨作者内容没有统一阅读入口、处理状态与内容混排，以及原文和规则摘句重复展示。

## 3. 信息架构

模块名称建议改为“创作者研究”，内部三个常驻入口：

1. **内容库**：默认页。视频、要点、原文、评论、来源证据。
2. **博主管理**：作者身份、新增/暂停、采集范围、检查频率、登录状态、最近成功记录。
3. **任务中心**：当前队列、历史任务、失败原因、针对性重试。技术日志放在展开项，不占默认阅读区。

桌面布局：

```text
WebStock · 创作者研究           内容库 / 博主管理 / 任务中心       + 添加博主
┌──────────────┬────────────────────┬─────────────────────────────────┐
│ 全部博主      │ 搜索 + 日期语义筛选  │ 视频标题 / 作者 / 真实状态          │
│ 作者 A        │                    │ 视频预览（按需展开）               │
│ 作者 B        │ 封面 + 标题         │ 要点 / 逐字稿 / 评论 / 处理记录      │
│ 作者 C        │ 发布时间 / 阶段状态  │                                 │
│              │                    │ 内容、原句引用与时间定位           │
│ + 添加博主    │                    │                                 │
└──────────────┴────────────────────┴─────────────────────────────────┘
```

- 大桌面作者栏约 208–224px，视频列表 340–380px，阅读区弹性铺开；不要把阅读字号随屏幕宽度压小。
- 1100–1439px：作者栏可收起；保留两栏阅读。低于 1100px 使用列表/详情切换，不硬塞三栏。
- 提供“专注阅读”，隐藏导航和列表但保留返回位置、播放进度、筛选条件。
- 正文限制行宽约 44–48em；正文 16–18px，常用操作 14px，次要元信息不低于 12px。长文不沿超宽屏从左读到右。
- 正式桌面可以采用明确的列表/阅读独立滚动；禁止卡片内再嵌套多层滚动。内嵌设计预览为适应对话宽度会较早折叠，不能作为最终应用断点验收结果。

## 4. 多博主接入：可理解、可控、可恢复

### 新增流程

1. 点击固定的“添加博主”。第一阶段直接重用现有完整主页链接能力，并提供清晰示例和错误提示。
2. 显示待确认的作者身份：平台、主页地址、平台标识；头像/昵称只有真实获取到才显示。无法验证时不能显示“已确认”。同名不同作者不合并，同一作者重复添加直接跳转已有项。
3. 选择首次采集范围：建议“最近 7 天，最多 20 条”；是否可按此限制需先核对现有分页/计划器接口，不能只在前端显示限制却仍全量抓取。
4. 选择增量检查频率（沿用 10 分钟作为默认建议），明确“检查频率不等于新视频必然在 10 分钟内成功入库”。首次历史补采与日常增量分离。
5. 完成后展示“已添加 / 排队中”，可直接查看任务；不能用“保存成功”冒充“采集成功”。

后续增强：解析分享文字与短链接，再展示真实身份供确认。必须限制平台域名、跳转次数、解析超时和返回体，拒绝本机/内网跳转，不执行链接文本中的指令；作品链接不应被误当作者主页。

### 管理列表

每行：头像/名字、平台身份、启用状态、采集范围、最近检查、最近成功取得新内容、待处理阶段、操作。将“检查成功但无新增”和“因登录/限流失败”分开显示。

- 暂停作者只停后续采集，不删除历史；暂停状态须在 channel/job/队列之间保持一致，具体实现前核验现有状态机。
- 多作者共享有界队列，避免每位作者各开一批并发浏览器；重试必须有退避与上限。
- 验证码与登录由用户完成，不绕过验证；后台运行与完全退出/休眠的差别直接说明。
- 批量添加不是第一阶段必做；先保证单作者新增、身份校验与状态反馈可靠。

## 5. 结果展示：先看结论，再追溯证据

### 视频列表

保留封面、两行标题、作者、发布时间、一个主要处理状态。把转写模型型号、文件路径、原始采集标识放入处理详情。缺少封面时显示明确占位，不拿其他视频图片替代。

提供作者筛选、标题/全文搜索（能力分阶段）、发布时间/任务处理时间切换、状态筛选。跨作者内容库需要服务端有界分页，不应把每个作者的 500 条全拉到浏览器再合并。

### 阅读区四个页签

| 页签 | 展示重点 | 不做什么 |
| --- | --- | --- |
| 要点 | 3–5 条有出处的摘录/概括、作者提及的公司或行业、条件与风险、定位原句 | 不把关键词命中直接包装成荐股；不无依据补充公司映射或收益结论 |
| 逐字稿 | 段落阅读 / 带时间轴二选一；点击时间定位本地视频；原始 ASR 与人工校订分版本 | 不同时展开两份全文；没有时间戳不能虚构定位；转写疑似错误须标注 |
| 评论 | 已保存评论、作者回复、采集时间与覆盖范围、刷新/补采入口 | “这次没采到”不是“没有评论”，也不是平台已删除；不覆盖删除历史快照 |
| 处理记录 | 发现 → 详情 → 归档 → 转写 → 提取 → 评论，各阶段状态与来源、失败原因、单阶段重试 | 不因评论失败把已成功的归档/转写清零；不因更新摘要重跑视频下载 |

当前规则提取结果应明确命名“规则摘录”，展示规则版本。模型摘要若后续接入，必须单独显示模型/生成时间/输入版本，并保留原文引用；原文不足、非投资内容或噪声严重时，展示“暂无可确认要点”，不复制全文凑满。

视频源失效但已归档可读：显示“本地归档可读，源链接当前不可用”，不把历史身份确认回退为待核验，也不无证据断言作者删除。只有可靠来源证明删除时才能写“源视频已删除”。

### 评论留存

以后续实现前的现有表结构核查为前提，按作者/视频/评论稳定身份保存观测版本，区分原始发表时间和采集时间。跨次未见不代表删除；展示“本次未观察到”与历史版本。仅用户明确删除本地记录才进入可恢复删除流程。

## 6. 视觉系统

参考 Linear 的紧凑产品秩序，不照搬营销页面：单一靛蓝操作色、轻边框、4px 间距节奏、低层级阴影、真实文字状态。与 WebStock 现有浅色/深色主题一致。

- 一个区域只保留一个主要操作；补采/重试是选中视频的次级操作。
- 绿色表示处理成功，琥珀色表示需处理，灰色表示未执行；都配文字，不能靠颜色猜。
- 股票涨跌红绿仅用于真实市场数值，与任务状态分开。
- 成功状态稳定显示，不每次轮询闪烁；后台轻量更新，不重建正在播放的视频。
- 不增加没有真实依据的“可靠度 95%”“主力观点评分”等商业化装饰数字。
- 键盘可操作、焦点清楚；中文长名称不被状态徽章挤没；窄屏不横向裁切主要操作。

## 7. 分阶段实施与验收

### A. 最小阅读重构（优先）

复用现有作者切换、新增、单视频动作；拆出三入口与详情四页签，放大正文，收起技术设置，规则摘录诚实命名。先不改变采集和数据结构。

验收：旧视频都可找到；切作者不会闪回上一个作者；切页签不重启播放；发布时间筛选不变；每个按钮作用对象明确；现有归档/转写/评论动作仍可用。

### B. 多作者工作流补齐

作者状态清单、持久化采集范围与暂停、跨作者内容分页、队列公平性、短链接解析（可单独开关）。已有接口先复用，需要新接口时另写字段与错误码合同再实现。

验收：同主页不重复、同名不同主页不串库；作者暂停不影响他人；一次失败不阻塞整队；范围配置确实限制采集；前端不会全量遍历作者历史。

### C. 阅读质量与历史证据

去重的规则摘录、原句定位、非投资内容/低质量文本提示、评论历史版本。可选模型摘要后置，不作为浏览历史内容的依赖。

验收：任何要点能追溯到原文；重新提取不抹掉旧证据；评论源失效仍可阅读已存版本；无数据、未采集和失败三种状态区分。

### 本轮原型检查（与业务验收分开）

独立预览已做脚本语法检查，并在浏览器检查作者切换、没有视频的作者空态、原句高亮、评论页签、演示新增、窄屏列表/详情切换。320、736、1024px 浏览器尺寸下测量根容器无横向溢出，检查时没有捕获到浏览器脚本错误。预览没有网络采集调用；这些结果仅证明设计原型可交互，不证明正式采集、多作者调度或真实视频播放已实现。

## 8. 明确不在本轮做的事
