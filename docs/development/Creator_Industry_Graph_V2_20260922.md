## 1. 目标与已确认事项

用户需要能解释产业、产品和公司的知识图谱，不是上中下游的公司卡片列表。每一条 Fioona 视频都进入文稿质量检查及分析流程；有产业内容就提取，无产业内容也留下已处理结论。

用户已确认：第一、第二梯队按同一细分业务中的产业地位划分；股价涨幅单独排序。

其余默认假设，仍待本规格审阅：

- 延续当前紧凑桌面布局、配色和程序身份；本轮不展开手机端改版。
- 图谱主层级是「产业主题 → 细分环节 → 产品/技术 → 公司」，公司层按产业梯队排布；可切换单公司视角。
- 市值及涨幅来自行情，业务来自公司正式资料，视频提供作者观点及研究线索；三者可关联，不混成同一种事实。
- 「全部概念」指纳入的数据源实际提供的完整概念集合，保留各自口径和覆盖；不是承诺穷尽所有市场标签。
- 本轮仅做需求规格、只读核验及用户指定对话的研究交接，不将未审阅的新提取结果自动导入生产。

                 │               ├ 第一梯队      │ 市值与近期涨幅
                 │               │  ├ 公司甲     │ 全部概念及数据来源
                 │               │  └ 公司乙     │ 原文/公告/视频与时间

上述公司甲乙为结构占位，不代表真实排名。

- 默认有序树形/有向图，不使用持续乱跳的力导向布局。上下游是环节属性，不能压成三个大空白列。
- 每个细分产品下，第一梯队在前/上，第二梯队随后；未知独立列为「尚未评定」，不能自动当第三梯队。
- 公司节点紧凑显示名称/代码、该分支业务、一项选定行情值和梯队。完整业务、概念与证据放详情，避免把全部文字塞进节点。
- 点击公司打开详情；展开控制与详情点击分开。可拖节点、平移、缩放、定位公司及一键恢复排序。
- 拖动仅改变展示坐标，不改变公司的梯队或事实；重新排序保留当前选中对象。
- 同一家公司只有一个规范身份；在不同业务分支可有镜像节点，点击均打开同一公司资料，并显示「还涉及 N 个业务」。同一分支去重。
- 边必须有类型：业务归属、产品组成、技术依赖、需求驱动、替代、供货/客户关系等；供货边必须有相应证据，不能由技术依赖推导。
- 关系的作者观点、外部资料、人工核验、存在争议状态分别表示，且不仅靠颜色区分。
- 首屏展开有限层级，折叠节点标真实子项数量，支持继续加载；不能用首屏截断冒充全量覆盖。

## 4. 公司信息与梯队规则

| 信息 | 具体要求 |
|---|---|
| 公司做什么 | 简短业务解释 + 完整业务/产品明细，列来源、报告期、核验状态；业务范围不直接等同于已实现营收 |
| 第一/第二梯队 | 绑定「细分业务、地理/市场比较范围、评价期间、标准版本、证据」；不是公司全局永久标签 |
| 梯队依据 | 优先可比口径的份额/行业排名，辅以有依据的技术、产能、客户验证；没有可比证据标未评定，不用市值、股价或提及次数代替 |
| 当前市值 | 标明总市值/流通市值、币种、行情时间；休市标最近交易日，更新失败保留旧值及陈旧提示 |
| 最近涨幅 | 建议 1/5/20/60 交易日，明确基准、价格复权及缺失状态；不足历史不填 0；不改变业务梯队 |
| 全部概念 | 全量保存数据源提供的概念记录，分页/展开完整可查；区分概念、行业、地区、指数成分等类别，显示来源和数量；相同概念合并展示仍保留各源名 |
| 公司多业务 | 一家公司可以在不同细分业务具有不同地位；不能在所有环节复制同一标签或一个总排名 |

例如长电科技，详情应回答「有哪些业务、各业务处在哪个环节、业务地位有什么依据」，而不是仅显示一个代码。本规格未实际核验长电当前市值或业务梯队，不在示意结构中编造数值及排名。

## 5. 每视频处理与更新要求

1. 以作者身份、平台作品 ID 为作品身份；完整保留原链接、标题、发布时间、采集时间、媒介类型。
2. 逐条统计转写情况：待采集、待转写、正文不完整/异常、待分析、分析中、已分析有关系、已分析无产业内容、失败待重试。图文不混入视频分母。
3. 先检查转写质量。只达到 30 字不代表完整；无语音、歌曲、疑似提示词回声和真正行业内容需区分。保留原转写及版本，不能用 AI 补写缺失原文。
4. 对全部可用正文逐段分析并合并，保留跨段关系；不再以每篇 4 条静默截断。安全长度/输出限制导致未完成时必须标部分，不能标整篇成功。
5. 分析身份至少包括作品 ID、正文哈希、分析规范版本。新规范可重审旧文，不被现行「同哈希已有记录就跳过」挡住；重跑相同版本幂等。
6. 提取产品/材料/技术/工艺/公司及关系，并定位文稿原文区间；没有明示证券身份时不强绑代码。ASR纠错建议单列，经依据核验后再采用规范术语。
7. 按作品发布时间显示新观点；未知发布时间保持未知。新观点不删除旧证据，冲突单列；不能把较新口播自动升级为正式公司事实。
8. 公司业务、概念、行情按各自来源补全，缺口可见。产业地位要另有比较标准及证据，不从语言模型印象直接写入。
9. 后台有队列、重试、覆盖和失败原因，不因切换页面丢任务；网络/AI在后台处理，避免主窗口同步重活，保留现有卡顿诊断。

自动化边界：程序当前没有可用 AI API。此次本地把实际正文交给既有 ChatGPT 对话是已授权的分析交接，不代表应用能自动调用该对话。持续无人值守需配置受支持的 AI 接口，或明确实现外部分析导出/回传队列；不得借用登录 Cookie/伪造 API 接通。

## 8. 验收标准

- 每条视频都有唯一处理状态，分母区分线上已发现、本地视频、可用全文；8 篇空关系也必须有原因，不丢失；未完整转写不能算全文分析完成。
- 回归含提示词回声、生活/歌曲空关系、正文改版、规范升级重审、跨段关系、超过4条关系、迟到回复、冲突及重复导入。
- 图谱有真实有类型连线，可展开、平移、缩放、拖动、复位。公司在同一业务分支不重复，跨业务镜像统一身份。
- 第一/第二梯队有领域、期间、比较依据；未知保持未评定。切换 20 日涨幅排序不改梯队数据。
- 公司详情能查看全部来源概念，不再只保留 24 项；缺值、旧数据和断网回退明确展示。
- 1366×768 和 1920×1080 实际浏览器检查紧凑布局、键盘选择、深浅色、完整概念展开、选择不被后台刷新打断。
- 对 1,000 公司/3,000 关系的合成压力集验证按需展开，明确是性能夹具而非真实产业数据；首屏目标可见节点不超过约80，折叠计数不能丢。记录交互延迟及诊断日志，不只报单元测试通过。
- 新包验收必须核对实际用户运行路径、数据目录和打包资源，生产切换前备份，单独取得退出授权；不能把源代码改完视作已更新。
