# 正常退出与稳定数据位置（2026-09-26）

## 已确认问题

旧版退出请求清除了轮询并关闭后台 HTTP/IPC，但没有等待当前采集/转写的结果保存。桌面进程仅等待 10 秒；转写耗时更长时会报退出失败，后台之后自行结束，桌面却仍保留。再次启动命中单实例，只显示这个后台已经停止的窗口。

## 决策

- 停止接收新的采集任务、续跑和定时轮询；当前作品处理完成并持久化后才释放服务连接。
- 等待所有已在执行的作者/单视频任务，以及采集队列的状态保存。不强杀 Python，不清空已有资料。
- 退出中断的多视频任务标记 interrupted/remainingCount，队列保持可续跑，不误报全部完成。
- 使用独立退出状态窗口，期间不能重新显示为正常可用页面。失败保留明确状态，允许重试退出。
- 在 startup.log 记录退出阶段；后台自身观察器保持到任务收尾之后。
- 新版支持第二实例 `--quit` 请求已有实例正常退出；部署前必须核对目标实例，不能将其当作进程强杀命令。

## 数据位置约定

可执行文件旁可选 `runtime-location.json`：

```json
{"schema":"webstock.runtime-location/v1","dataDir":"D:/WebstockRuntime/data"}
```

显式目录同时作为业务数据和 Electron 用户资料目录，保持数据库、登录会话、媒体、模型、量化工作空间与诊断信息共同归属。声明存在而目录/数据库缺失时停止启动，禁止回退到空数据库。未提供该文件的旧便携用法继续使用 EXE 同级 WebStockData。

推荐本机目录：app 只放当前程序及定位文件；data 是唯一正式可写数据；runtime 放独立 Python 环境；backups 保存停写后的完整回退副本；releases 保存少量可回退程序包。应用身份 appId、app.setName、登录分区与 API 协议不改。

打包排除 quant 的虚拟环境、工作空间、下载模型和媒体。迁移前停写并校验；本机绝对媒体路径只重定位原目录前缀，不修改来源 URL、文稿内容和证券数据。旧库独有资料另存，不按记录数认定可删除。

## 验证边界

定向回归涵盖在途保存、失败落库、重复退出、退出失败重试、长于 10 秒的子进程、增量中断续跑和数据目录缺失保护。构建验证使用隔离数据库和端口；原生窗口验证使用隔离目录和合成子任务。它们不代替正式实例的路径、数据数量、媒体引用与正常退出/重开核验。

本机执行记录与哈希清单保存在 runtime-folder-audit-20260926 诊断目录及 WebstockRuntime/backups，不将个人数据库、登录状态或凭据提交到 Git。
