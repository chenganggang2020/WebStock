## 结论

此前并非完全没有改动：首页联动、自选组来源、主图与盘口复用、紧凑公共样式已经接入。但这不等于所有页面完成结构改版，也未达到用户最新的“固定页面高度、内部滚动、附加模块独立打开”要求。

26 个导航入口 = 18 个核心视图 + 8 个同页定位。原始 Compact V2 的 PAGES.md 本来就说明“不是新增 26 个生产路由”。现在的接入保留了同页跳转和旧长页；需要改变视图组合，不应继续仅缩字号/间距。

## 弹窗 / 卡住：已知与未知分开

### 已确认

1. `js/modules/sectorLeaders.js:78` 调用 `/api/sector-leaders/dashboard`。
2. `js/modules/apiClient.js:27` 默认超时 12,000ms。此接口未进入 35 秒的行情专用分支；超时后产生截图中的“请求超时”文本。12 秒是整体请求预算，不是 3 次各 12 秒。
3. `js/app.js:380` 和 `:556` 将错误交给原生 `alert()`，用户必须点击确认才能继续操作该窗口。它是“看起来卡住”的明确交互原因，不等于已证明进程死锁。
4. `services/sectorService.js:325` 在此请求中直接向新浪抓取整批代码，设置 6 秒超时；异常返回空行情映射。
5. `services/sectorService.js:358` 的 `getDashboard()` 随后逐条调用 `recordLeaderSnapshot()`，同步向 SQLite 插入快照。读看板触发取行情与落库，没有在这个函数中分离缓存读取与采集。
6. 本轮健康接口返回 HTTP 200，`database:ok`，约 0.00085 秒（单次观测，不是性能基准）。本轮未捕获故障当时的请求耗时。

### 尚不能定论

仅凭截图不能确认超时主要来自网络、同步数据库写入、其他后台任务竞争还是 Electron 线程阻塞。6 秒上游超时本身也不足以解释前端 12 秒超时。没有足够的故障时段追踪，不归咎为唯一根因。

### 下一轮拟修复

- 自动刷新失败改为模块内提示，保留最后成功数据及时间，单独重试。无需原生确认框；故障详情放“数据与运行健康”。
- 看板 GET 读最近快照；刷新采集与持久化由受控任务完成，同源请求合并，避免多页面重复抓取/写入。
- 分别记录请求排队、上游、数据库、序列化耗时；传递取消信号、设置整体预算。
- 数据失败不写零值、不把检查时间标成行情更新时间。
- 以注入慢上游/数据库锁/断网的隔离测试复现，并验证出错后仍能切页与选股。暂不直接实现上述后端变更。

为保持本轮只读，发现 GET 看板会写快照后，没有为了测时反复调用这个接口。

## 统一布局约定

- 桌面工作区占满可用窗口；导航、上下文、工具条、状态栏固定。页面本体不纵向滚动。
- 允许滚动的是股票列表、结果表、逐字稿、正文、证据和日志。表头固定、各区位置独立保持；不能用 `overflow:hidden` 简单裁掉内容。
- 首页左栏：分组下拉（保留“本地 / 同花顺只读”来源）+ 搜索 + 股票列表。不再永久显示全部组名。
- 首页默认：上指标、中主图、右盘口。市场全景、榜单、个股研究分别从入口打开，不再堆在下方。榜单单独切换优先于固定占据图表高度。
- 资金类去掉整体居中限宽，改满宽工作区；四个标签真正切换可见区域，不再滚动到长页中部。
- 研究类：左目录、中内容、右证据；阅读正文可保留合理行宽，但整页不可变成窄列。
- 采集类：作者/任务目录 190px；视频列表约余宽 40%；详情约 60%。播放、逐字稿、评论、任务为详情内部标签。
- 延续原包：44px 主导航、约 30px 子导航、33px 面板标题、6px 间距、3px 圆角、默认 30px 表行（可选 34px）。不添加新品牌，深浅色沿用 Compact V2。
- 小窗口优先切换区域/展开详情，而非压到不可读或悄悄隐藏内容。手机页面单独评审，不将桌面验证冒充 iPhone 验证。
