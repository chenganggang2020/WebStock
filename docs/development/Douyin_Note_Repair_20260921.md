# 抖音图文采集修复记录 · 2026-09-21

## 范围

本任务仅修复现有桌面程序的图文采集、正文检索和阅读显示。整程序手机适配在独立任务“全程序手机适配：移动端界面与改造方案”研究，不混入本修复包。

源码基线为 `D:/Webstock/output/recovery-20260920/source`。旧根目录及正在运行的用户数据库不直接修改；不改应用身份、登录会话分区或便携版数据目录。

## 已确认原因

1. 作品页通用作者链接可能先匹配到评论者，导致正确作品被误判为另一作者而拒绝导入。
2. 当前公开图文页的完整详情可能在流式 SSR 数据里，不一定通过单独的详情请求返回；仅识别旧 snake_case 结构会漏掉作者、发布日期和原图。
3. 原处理链主要围绕视频下载及语音转写，图文没有原图归档、图片文字识别和正文展示链路。
4. 全量队列只统计视频，图文首批结束后可能提前认为任务已完成。
5. 标题衍生的规则摘要曾进入知识索引；没有实际正文时不应视为已采集知识。

## 修复决策

- 作者必须与当前作品 ID 绑定，继续保留登录、验证码及身份核验边界。严格解析 JSON 数据，不执行页面脚本。
- 同时支持详情接口与当前页面的 SSR 详情。保留作品类型、原始发布时间和图片顺序。
- 图文走独立处理分支：保存原图 → Windows OCR → 逐页保存正文和状态 → 建立正文检索。图文不送入语音转写。
- 图片仅允许指定 HTTPS 图片源域名，不跟随重定向；单图上限 16 MB，单作品本轮最多 50 页，有处理超时上限。未完成部分显式标记为 partial。
- OCR 保留原始输出和规范化文本，标注待校对；原图使用内容哈希保存，变化时不覆盖旧原图。
- 部分重试保留此前成功页，并标注此前版本，不把混合保留结果声称为本次全部成功。
- 队列计数包含图文；OCR 错误进入原有退避机制，成功重置失败累计。
- 本地图片通过作者、作品、页码、哈希及真实路径共同核验后提供，避免跨作者读图。

## 新增只读图片接口

`GET /api/expert/channels/:id/observations/:oid/images/:page`

只提供当前作者当前图文记录已归档的图片；找不到或路径不匹配返回不可用，不从请求参数直接拼接任意文件路径。现有观察记录中的 `mediaMetadata.note` 保存逐页状态、哈希、文本和本地路径；不保存临时签名图片 URL。
