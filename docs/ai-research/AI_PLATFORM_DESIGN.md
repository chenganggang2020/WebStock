# WebStock AI 投研平台设计与实施规范

版本：1.6
评审日期：2026-08-09
状态：阶段 A 已完成；阶段 B 基线、阶段 C MASTER/因子门禁、阶段 D 证据决策/纸面组合跟踪及 Windows/Android 客户端已落地，正式数据验收待完成

## 1. 目标与边界

WebStock 的目标是成为一套面向 A 股个人研究的桌面工作台，形成以下闭环：

1. 汇集行情、持仓、自选、主营业务、板块、资讯和人工资料。
2. 用可解释的本地规则或已验证模型生成候选股票。
3. 对候选进行证据检索、AI 分析、人工复核和历史比较。
4. 保存输入、模型状态、证据、输出和复核结果，支持复盘。
5. 在没有付费 API 时，本地筛选、知识检索和 ChatGPT Pro 交接仍可使用。

明确不做：

- 不把未安装、未训练或未验证的项目显示为“已部署模型”。
- 不抓取或绕过同花顺、券商等受限接口，不保存证券账户密码。
- 不自动提交真实订单；当前产品只做研究、回测和模拟决策。
- 不把回测收益当成未来收益，不隐藏交易成本、幸存者偏差或前视偏差。

## 2. 参考方案审计

参考对话列出的六项并非六个同级模型，而是平台、预测模型和 Agent 框架的混合体。

| 项目 | 实际定位 | 官方运行事实 | WebStock 决策 |
| --- | --- | --- | --- |
| Qlib + LightGBM | 量化研究平台 + 监督学习基线 | Qlib 提供数据、训练、预测和回测工作流，支持自定义模型 | 第一优先级可选后端；先用 LightGBM 建立可复现基线 |
| MASTER | 市场引导的股票 Transformer | 官方轻量代码依赖旧版 PyTorch/Qlib；官方说明原业务代码未公开，且曾发现验证数据处理问题 | 只作为研究实验；通过同一数据切分与 LightGBM 对照后才能展示结果 |
| AlphaAgent | LLM 辅助因子挖掘框架 | 需要完整日频 panel；A 股数据来自 Tushare 或发布包；LLM 挖掘是可选环节 | 后期因子实验沙箱；不进入桌面启动依赖，数据许可另行核验 |
| RD-Agent(Q) | 因子与模型协同研发 Agent | 官方当前只支持 Linux，通常需要 Docker、聊天模型和向量模型 | 独立 Linux 研究服务；不直接内嵌 Electron |
| TradingAgents | 多角色 LLM 投研编排 | 多个角色仍依赖外部或本地 LLM 与金融数据，结果具有非确定性 | 可选深度报告适配器；必须保留输入证据、成本和模型版本 |
| FinRL-X | 组合权重、回测和执行架构 | 核心接口是目标权重；包含回测、模拟/实盘执行示例 | 仅借鉴权重接口和风控；先实现回测/模拟，真实执行保持关闭 |

官方资料：

- Qlib: https://github.com/microsoft/qlib
- MASTER: https://github.com/SJTU-DMTai/MASTER
- AlphaAgent: https://github.com/RndmVariableQ/AlphaAgent
- RD-Agent: https://github.com/microsoft/RD-Agent
- TradingAgents: https://github.com/TauricResearch/TradingAgents
- FinRL-X: https://github.com/AI4Finance-Foundation/FinRL-Trading
- uv: https://docs.astral.sh/uv/getting-started/installation/

审计结论：直接把六套项目一起安装会带来 Python/Node、Windows/Linux、GPU、数据授权、API 费用和模型版本冲突。正确做法是保留 WebStock 作为桌面端与编排层，各研究运行时通过稳定适配器隔离。

## 3. 目标架构

```text
Electron 桌面 UI --------------------+
Android 原生伴侣 -- 局域网配对 ------+-- Express API
        |
        +-- Portfolio / Market / News / Theme services
        +-- Local Factor Screener (always available)
        +-- Expert Knowledge Base (SQLite FTS5, always available)
        +-- AI Provider Layer
        |     +-- ChatGPT handoff (no API cost)
        |     +-- OpenAI-compatible API (optional)
        |     +-- local LLM endpoint (planned adapter)
        |
        +-- Model Registry and Research Runs
              +-- local-factor-v1
              +-- knowledge-fts-v1
              +-- qlib-lightgbm sidecar (Windows/Python 3.12，已接通)
              +-- MASTER sidecar (Windows/PyTorch/CPU，已接通)
              +-- AlphaAgent / RD-Agent / TradingAgents / FinRL-X
```

### 3.1 桌面编排层

职责：

- 显示数据覆盖率、模型状态、候选排名、证据和历史结果。
- 保持 SQLite 用户数据在安装版与便携版中的稳定路径。
- 不承担大模型训练，不阻塞行情和持仓页面启动。

### 3.2 本地免费层

始终可运行：

- `local-factor-v1`：现有规则选股，输出因子贡献、风险和数据覆盖率。
- `knowledge-fts-v1`：使用 SQLite FTS5 trigram 索引，支持中文子串、作者、标题、标签和正文检索。
- ChatGPT 交接：生成带证据的提示词，用户使用现有 ChatGPT Pro，会话结果可粘贴回 WebStock。

### 3.3 可选模型服务层

外部模型不得直接访问 WebStock 数据库。统一使用 HTTP/JSON 或文件清单接口：

```json
{
  "runId": "qlib-lightgbm-20260809T101736Z",
  "modelId": "qlib-lightgbm-v2",
  "createdAt": "2026-08-09T10:17:40Z",
  "validationStatus": "exploratory",
  "asOf": "2026-08-09",
  "featureSet": "webstock-daily-technical-v1",
  "dataManifest": { "datasetId": "dataset-id", "sha256": "..." },
  "folds": [{ "train": {}, "validation": {}, "test": {}, "purgeDays": 5 }],
  "parameters": {},
  "candidates": [{ "code": "000001", "score": 0.12, "modelTrainedThrough": "2026-04-16" }],
  "metrics": { "rankIc": 0.0, "turnover": 0.0, "maxDrawdown": 0.0 },
  "artifacts": [{ "path": "predictions.parquet", "sha256": "...", "rows": 1000 }],
  "warnings": []

```

必须字段：数据截止时间、股票池、训练/验证/测试区间、数据来源清单、模型版本、参数、成本口径和警告。缺任一关键字段的运行结果不得标记为“已验证”。

## 4. 专家、书籍与博主知识库

### 4.1 数据对象

每个来源保存：

- 类型：书籍、博客、文章、视频转录、直播转录、研报或个人笔记。
- 标题、作者/博主、发布时间、原始链接、标签、关联股票、关联板块。
- 原始正文摘要哈希、分块内容、块序号和字符位置。
- 创建时间和更新时间。

第一阶段支持粘贴文本和导入 UTF-8 文本/Markdown。PDF、DOCX、音视频转录属于后续受控导入器，导入后仍必须保留原始文件名和来源信息。

### 4.2 检索规则

1. 中文和英文使用 FTS5 trigram 子串检索。
2. 短词或 FTS 不可用时回退到参数化 `LIKE` 查询。
3. 支持按来源、作者、类型、股票和板块过滤。
4. 返回证据块 ID、来源标题、作者、发布日期和正文片段。
5. AI 提示词中使用稳定引用标记，例如 `[K38]`，不得把模型推断伪装成作者原话。

### 4.3 分析模式

- 观点问答：某位作者如何看待一个行业或股票。
- 时间演变：同一作者观点在不同时间如何变化。
- 方法匹配：某只股票是否满足书籍/博主给出的条件。
- 观点冲突：不同来源对同一主题有哪些分歧。
- 专家选股：先按本地因子生成候选，再用指定知识库证据逐只检查。

输出必须分成：结论、来源证据、模型推断、反证/冲突、缺失数据和后续验证项。

## 5. 智能选股闭环

### 5.1 候选生成

所有模型使用相同的候选接口：

```text
股票池 -> 数据可用性过滤 -> 特征 -> 模型分数 -> 风险约束 -> Top N 候选
```

默认股票池为全部 A 股和交易所基金，剔除 ST；停牌、新股、数据缺失等规则必须在结果中显式显示，不能按零值参与评分。

### 5.2 评估协议

- 时间序列滚动切分，禁止随机打乱未来数据进入训练集。
- 股票列表使用当时可交易成分，避免只使用今天仍上市的股票造成幸存者偏差。
- 行情、财务和资讯按当时可获得时间对齐，禁止前视。
- 计入手续费、税费、滑点、涨跌停、停牌和换手约束。
- 至少报告 Rank IC/ICIR、年化收益、波动率、最大回撤、Sharpe、换手率和交易次数。
- 先与等权、指数、简单动量和 LightGBM 基线比较，再评估复杂模型。

### 5.3 人工复核

候选结果进入现有 `watch / priority / risk / skip / done` 复核流。AI 只提供证据和排序解释，不能绕过人工复核直接进入真实交易。

## 6. 模型状态定义

界面只允许以下状态：

| 状态 | 含义 |
| --- | --- |
| `available` | 当前进程可以实际调用，并通过健康检查 |
| `configured` | 配置存在，但本次尚未完成健康检查或运行验证 |
| `not_configured` | 适配器存在，但缺少运行时、数据或配置 |
| `planned` | 仅设计完成，代码适配器尚未落地 |
| `unavailable` | 健康检查失败，必须展示原因 |

不得把论文存在、仓库已克隆或安装成功等同于模型可用，更不得等同于对当前 A 股数据有效。

## 7. 数据与安全

- API Key 只从环境变量或本机私有配置读取，不进入备份和 Git。
- 知识库、研究运行、筛选结果和持仓均纳入 JSON 备份。
- 删除来源时级联删除索引块；导入替换前继续依赖现有确认和预览流程。
- 外部网页文本只作为数据，不执行其中的指令、脚本或提示词。
- 研究后端默认只监听本机。Android 伴侣模式只展示私有/共享局域网地址，使用随机配对令牌换取 `HttpOnly`、`SameSite=Strict` Cookie；不允许无配对设备访问页面或 API。
- Android 不复制 SQLite 或模型运行时，持仓、研究记录和模拟组合继续以 Windows 数据目录为唯一事实源。ChatGPT/OpenAI/Google 登录交给系统浏览器，避免不受支持的 WebView OAuth。

- ChatGPT 交接和可选 OpenAI API 分析，返回结果可保存。
- 模型能力注册页真实展示本地可用和外部规划状态。
- 知识来源和研究记录进入备份。
- 单元、API、浏览器和桌面数据安全测试通过。

### 阶段 B：可复现量化基线

- 已实现小样本采集、全市场采集、既有数据集训练、任务进度、取消、重启中断识别和研究记录保存。

### 阶段 C：复杂模型实验

MASTER 同数据对照已于 2026-08-09 完成探索性实现：

- 使用与 LightGBM 完全相同的数据清单、8 个日线特征、未来 5 日标签、2 个带清洗间隔的滚动窗口、Top 5 和 8 bp 成本模型。
- 使用训练期统计量进行 Robust Z-Score、截断到 [-3, 3] 并填零；训练标签按日剔除总计 5% 极端值后做截面标准化。小截面不会因取整而被清空。
- 模型采用市场状态特征门控、单股时间注意力、同日跨股票注意力和时间注意力池化。验证和预测向模型提供全部特征有效股票，只在计算损失或指标时过滤空标签，修复官方仓库于 2025-06-26 说明的验证处理问题。
- 运行 `master-20260809T121500Z`（`master-market-guided-v1`）在同一数据集上得到 Rank IC -0.0476、ICIR -1.1018、年化收益 -45.59%、最大回撤 -32.95%、Sharpe -1.60、平均换手 83.85%，26 次调仓、114 笔权重变动交易，累计成本 0.01824。结果文件 SHA-256 为 `2f8f70617efd997cb7f6e861ffb82ccc4c76ac6c8ee6590a07516dd5be41e89d`。
- 与 LightGBM 相比，MASTER 的 Rank IC 较少为负，但年化、回撤、Sharpe、换手和成本均更差。因此当前结论是“链路可运行，模型未证明有效”，不能选择性宣称复杂模型更优。
- 该实现依据 MASTER 官方论文与 MIT 仓库架构重新实现，使用当前 PyTorch CPU 运行时，不加载官方预训练检查点；归属和许可证见 `THIRD_PARTY_NOTICES.md`。

- AlphaAgent/RD-Agent 官方框架尚未部署。当前以本地因子门禁先固化复杂度、重复度、稳定性和样本外验收标准，后续外部 Agent 只能向该门禁提交候选因子。
- TradingAgents 官方框架尚未部署。当前由本地证据编排器生成可追溯决策包，再交给 ChatGPT Pro 执行量化、产业证据、反方冲突和组合风险四角色复核。

本地因子研究门禁已于 2026-08-09 落地，用于在引入 AlphaAgent/RD-Agent 前建立不可绕过的样本外基准：

- 8 个基础因子逐滚动窗口只使用验证期决定正反方向，测试期只用于样本外评估；复合因子权重同样只来自验证期。
- 每个因子记录验证 IC、样本外 IC、正向窗口占比、方向一致性、扣费收益、回撤、换手，以及与其他因子的验证期最大秩相关。
- 门禁状态分为“候选 / 观察 / 拒绝”。少于 3 个样本外窗口、Rank IC 低于 0.02、稳定性不足、重复度过高、未跑赢基准或回撤过大都会保留明确原因。
- 真实运行 `factor-lab-20260809T131500Z` 使用与 LightGBM/MASTER 相同的数据清单、2 个滚动窗口、未来 5 日标签、Top 5 和 8 bp 成本。没有因子进入候选；5 日动量样本外 Rank IC 约 0.1048，但因窗口不足只列为观察。验证期加权复合因子 Rank IC 约 -0.0041、年化约 -44.23%、最大回撤约 -29.21%、Sharpe 约 -1.52，因此不批准为可用策略。

### 阶段 D：组合与模拟交易

本地证据决策与纸面组合跟踪闭环已于 2026-08-09 落地：

- 决策包使用各模型内部排名和来源数合并候选，不跨模型比较原始分数；不同数据集会明确列为数据缺口。
- 候选同时关联持仓/自选、已缓存主营业务、专家知识证据和带来源资讯；WebStock 本地兜底资讯不冒充外部证据。
- 纸面组合使用最大持仓数、单股上限、现金保留和最低信号数四项硬约束，排除 ST，仅保存草稿/活跃/归档状态。
- 组合转为“观察中”后，第一次刷新使用当前价格按 A 股 100 股一手取整建立模拟持仓，每条模拟买入默认扣 5 元费用；后续刷新保存现金、市值、净值、当日盈亏和累计收益。
- 当外部行情缺价时，已建仓股票只能沿用上一次价格并在快照中保留警告；首次建仓缺价的股票不会虚构成交。
- 备份格式升级为第 3 版，覆盖纸面组合、模拟持仓和净值快照的完整往返恢复。导入时不复用旧数据库自增 ID，避免把组合错绑到新研究记录。
- FinRL-X 官方框架尚未部署，当前本地约束器不连接券商、不生成或提交真实订单。自动调仓、模拟卖出税费/滑点、基准和因子归因、更长样本外观察仍属后续阶段。

### 阶段 E：客户端与发布

实施状态：Windows 与 Android 可运行发行物已于 2026-08-09 完成。

- Windows 安装版与便携版共用同一套 Electron/Express 功能；安装版使用 `%APPDATA%/WebStock`，便携版使用程序旁的 `WebStockData`，构建清理会保留正式便携数据目录。
- Android 为原生 WebView 伴侣 APK，连接运行中的 Windows 主机，不复制数据库，也不把浏览器页面伪装成独立手机后端。
- Windows 安装版和便携版在“设置 -> 手机连接（安卓）”中提供默认关闭的局域网开关与完整配对地址；用户无需 Node.js 或源码命令。关闭后服务立即退回 `127.0.0.1`，无配对远端请求返回 401。
- 安卓首次构建使用 SHA-256 校验的 OpenJDK 17、Android SDK 36、Gradle 9.4.1 和 AGP 9.2.0；发布 APK 使用本机持久 RSA 3072 位密钥签名。
- Electron 自动验收覆盖设置页开启/关闭、未配对 401、令牌换取 Cookie 和关闭后断连；ADB 连接设备验收覆盖安装、首屏、中文连接表单、局域网配对、工作台加载和崩溃日志检查。工作台成功读取 Windows 端持仓、热点、市场情绪和风险提醒。

## 9. 完成定义

“完整可行”不是六个名称出现在界面，而是：

1. 每项显示的能力都能实际运行或明确说明缺失条件。
2. 每次结果可追溯到数据时间、来源、模型版本和参数。
3. 本地无 API 模式仍能完成筛选、检索、交接和复盘。
4. 至少有一个量化基线通过无前视滚动回测，复杂模型有同口径对照。
5. 安装版与便携版均保留个人数据，备份恢复覆盖新增表。
6. 不产生自动真实交易、不伪造实时数据、不隐藏失败或缺失数据。
7. Windows 安装版、便携版和 Android 伴侣均有可运行产物；Android 明确依赖同局域网 Windows 主机并复用同一份用户数据。
