# WebStock 自选量化研究闭环规格

版本：1.0  
日期：2026-08-28  
状态：已实施并完成本机验收

## 1. 目标

把当前分散的“同花顺自选、历史数据、策略回测、AI 分析、每日候选”串成一条可实际运行、可复查的个人研究流程：

1. 读取一个本地同花顺自选分组，不修改同花顺文件。
2. 为该组证券获取同一截止日的历史日线，并保存不可变数据清单。
3. 使用明确的 A 股成交假设运行多折样本外回测。
4. 只用通过门禁的规则生成最近收盘日候选，并展示反证和缺失数据。
5. 生成本地确定性解读；配置 API Key 时可追加 AI 报告，没有 Key 时提供 ChatGPT 交接。
6. 不自动下单，不把候选写成收益承诺。

## 3. 第一阶段用户流程

在“AI研究”页面增加“自选研究”卡片：

1. 数据来源下拉框列出“同花顺自选”和本地同花顺自定义分组。
2. 默认选择“同花顺自选”，显示证券数量、读取时间和文件来源。
3. 用户点击“刷新数据并回测”。
4. 程序只读取得该组 8–120 个六位证券代码，固定研究区间为最近五年到最近已完成交易日。
5. 程序生成独立数据集并依次运行均线、MACD、RSI、放量突破四类策略。
6. 页面持续显示“取数、校验、四类回测、候选合并”进度，不长时间只显示加载中。
7. 完成后显示数据覆盖、复权口径、费用、折数、最佳/最差参数、门禁结论、候选、反证和警告。
8. 候选可双击进入 K 线；不自动加入自选、持仓或同花顺荐股分组。
9. “AI解释”在有 API Key 时调用现有 OpenAI 接口；无 Key 时生成带完整证据的 ChatGPT 交接文本。

## 4. 数据与回测契约

- 数据集必须记录证券列表、来源、起止日、复权方式、每只证券行数、失败代码和 SHA-256。
- 首选可稳定获取的前复权日线；数据源超时或不可用时不得静默改成未复权。
- 如果只能获得未复权数据，结果必须标记 `exploratory_only`，不得称为正式策略验证。
- 股票名单取自当前同花顺分组，因此必须显示“当前成分股票池，存在幸存者偏差”。
- 所有信号只使用当时已经出现的数据；收盘信号最早在下一可成交交易日开盘执行。
- 回测保留 T+1、100 股整数手、涨跌停/停牌不可成交、佣金、最低佣金、印花税和滑点。
- 至少 3 个互不重叠样本外窗口；少于 3 折只显示“样本不足”。
- 每个候选必须能追溯到策略、参数、样本外指标、信号日期和最早观察时间。
- 被淘汰参数不得产生候选；候选为研究清单，不是买入建议。

## 5. AI 分析契约

AI 只解释已经生成的结构化结果，不得：

- 修改回测数值、补造缺失行情或隐去失败策略；
- 把历史最佳参数称为未来最优参数；
- 在无数据时直接给股票结论；
- 生成或调用交易接口。

AI 输入包含数据清单、截止日、费用假设、逐策略门禁、候选证据、反证和数据限制。输出固定分为：数据可信度、策略证据、候选观察顺序、主要风险、下一步人工核验。

## 6. 荐股/候选边界

页面用词统一为“研究候选”，不显示虚构胜率或热度分。排序依次使用：

1. 通过门禁的策略家族数；
2. 样本外正收益窗口占比；
3. 样本外中位收益；
4. 最大回撤较小者；
5. 股票代码作为稳定排序键。

若没有合格候选，必须显示“本次没有候选”，不能使用被淘汰参数补足数量。

第二阶段才增加“预览同花顺每日荐股分组”；必须先预览并由用户显式确认，不能后台自动改写主自选。

## 7. 实施任务

### 切片 A：后端自选研究任务

- 读取指定同花顺分组并验证 8–120 个证券代码。
- 让现有采集器真实接收代码列表，而不是取股票文件前 N 只。
- 新增一个编排任务：采集同源数据后运行四策略并生成同源候选报告。
- 验收：API 测试证明传入代码与清单一致，失败代码和数据口径明确，任务不含订单路径。

### 切片 B：AI研究页面闭环

- 增加分组选择、数量/来源提示、运行按钮、阶段进度和报告视图。
- 候选双击进入股票 K 线；空候选、数据失败和超时均有明确状态。
- 验收：桌面和窄屏真实浏览器可完成一次流程，控制台无错误。

### 切片 C：本地解释与可选 AI

- 先生成确定性中文摘要，确保没有 API Key 也可用。
- 有 Key 才开放自动 AI 报告；无 Key 提供 ChatGPT 交接。
- 验收：AI 输入只含结构化证据，失败时保留本地摘要，不把旧 AI 报告冒充新结果。

### 切片 D：同花顺荐股预览

- 将合格候选转换为 `00_每日荐股_MMDD` 预览。
- 只有显式确认后才调用现有备份、原子替换和 XML 校验流程。
- 验收：不修改主自选，失败可恢复，候选为 0 时禁止写入。

## 8. 技术结构与命令

代码继续沿用现有 CommonJS、原生 JavaScript、Express 和 Python 风格，不新增回测框架依赖，不直接复制 KhQuant V3 私有/内测代码。

## 9. 边界

- 始终执行：输入校验、数据来源/时间/复权披露、哈希、无未来数据测试、交易成本测试、失败可见。
- 实施前确认：第一阶段默认研究“同花顺自选 90 只”，而不是重新跑 5315 只全市场。
- 后续再做：全市场增量更新、历史成分/ST 点时点数据、更完整复权源、参数显著性和纸面组合追踪。
- 永不执行：自动真实下单、绕过同花顺/券商权限、将回测或 AI 输出包装成收益保证。

## 10. 成功标准

1. 用户可从真实同花顺分组一键创建同代码数据集并运行四类策略。
2. 报告至少包含 3 折样本外证据、A 股执行成本、数据截止日和复权口径。
3. 候选只来自通过门禁的参数；没有候选时诚实为空。
4. 没有 API Key 时仍有完整本地摘要和 ChatGPT 交接。
5. 页面不卡死，任务可观察、可停止、可复查。
6. Node、Python、浏览器验收与 Windows 便携版健康检查全部通过。

## 11. 待确认项

建议第一阶段采用：**同花顺自选/单个分组（8–120 只）优先**。它能在可控时间内形成真实闭环；全市场 5315 只增量数据更新作为下一阶段单独实现。
