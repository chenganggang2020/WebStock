# 抖音自动采集与创作者研究工作台规格

## 目标

让 WebStock 在 Windows 桌面程序运行期间独立执行抖音创作者采集，不依赖用户停留在 AI 研究页面；关闭主窗口时转入系统托盘继续工作。前台以覆盖率、队列、主题和视频详情为核心展示，不再把抖音资料默认呈现为长记录列表。

## 假设

- 自动采集只读取用户已登录后合法可见的公开页面，不绕过登录、验证码、反爬或权限控制。
- “独立运行”指 WebStock 进程在后台和系统托盘中继续工作；用户明确退出程序后停止采集，不安装 Windows 系统服务。
- 现有 SQLite 数据库和 Python 3.12 量化环境继续复用，不安装第二套运行环境。
- 页面能够发现多少历史视频受抖音公开页面当前可见范围约束；系统保存来源和失败状态，不宣称已恢复不可访问或已删除内容。

## 功能范围

1. Electron 启动时为所有已启用且配置主页的抖音创作者建立采集任务。
2. 主窗口关闭后隐藏到系统托盘，采集调度、数据库和本地 ASR 保持运行。
3. 托盘菜单提供打开主界面、立即检查全部创作者和完全退出。
4. 单次调度按有界队列抓取详情和转写，分别记录详情状态、媒体地址是否可用、下载/识别阶段、完成、顺延和失败原因。
5. 独立的“采集任务”页面默认展示实际网络路径、五阶段流程、最近运行明细、转写覆盖率、主题分布、视频列表和选中视频详情。
6. 原始录入和删除能力保留在折叠的资料管理区域，不作为默认阅读界面。

## 技术与文件

- `electron/main.js`：桌面生命周期、托盘和全频道任务初始化。
- `electron/douyinAutoSync.js`：有界采集队列和覆盖率结果。
- `services/douyinSyncStateService.js`：分别持久化当前流程进度、上次完成结果、每次运行及逐视频阶段明细。
- `electron/networkRoute.js`：读取 Electron 抖音持久会话实际解析出的代理或直连路径。
- `index.html`、`js/modules/expertTracker.js`、`css/styles.css`：创作者研究工作台。
- `test/*.test.js`、`test/frontend-click.spec.js`：调度、状态和前端回归。

## 命令

- Node 回归：`npm test`
- 前端回归：`npm run test:frontend`
- 量化回归：`npm run test:quant`
- Windows 打包：`npm run dist:win:all`

## 验收标准

- 用户关闭主窗口后，WebStock 进程和 10 分钟调度仍在运行；托盘可恢复窗口或完全退出。
- 新增的任意已启用抖音创作者在下次启动时拥有持久化采集任务，不再硬编码单一频道。
- “主页总作品”“本轮页面加载”“本地抖音作品”必须作为不同口径展示，不能互相替代。
- 未取得可下载媒体地址时必须显示“等待媒体地址”，不能显示为已进入转写队列；只有实际调用本地 ASR 才计入转写尝试。
- 最近运行可以展开查看每条候选视频的详情采集、媒体永久归档、本地识别、失败原因、媒体大小和耗时。
- 运行中的任务可以明确显示会话、发现、详情、转写和入库阶段；桌面端同时显示 Electron 当前解析到的代理端点或直连状态。
- 抖音页面首屏不再渲染长记录流，点击视频后在同一工作台显示原始逐字稿、时间戳、页面摘要和投资主题。
- 新增测试通过，完整 Node、前端与量化测试通过，重新生成的两个 EXE 可启动。

## 边界

- 始终：保留公开来源 URL、证据等级、时间、ASR 原始文本和已完成的本地媒体归档；远端删除或不可用不得联动删除本地数据，只清理未完成的 `.part` 临时文件。
- 不做：后台模拟人工登录、自动处理验证码、恢复已删除视频、自动下单或把推断写成本人原话。
- 资源控制：详情和 ASR 串行、有上限；后台页面保持静音并在采集后暂停媒体。
