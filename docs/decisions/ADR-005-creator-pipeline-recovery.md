# ADR-005：采集材料持久归档与文稿处理的独立恢复

状态：Proposed，待用户确认；仅方案，尚未实施。
日期：2026-09-26。

## 背景

当前运行版已实现采集、ASR、OCR和产业链提取，但只迁移数据库导致外部媒体、模型、环境关联和分析文件未接续；登录检查又阻断了本可离线执行的处理。真实 OCR 写入 `.note`，行业准入读取 `.ocr`；采集完成状态、文稿质量与分析就绪被混用。

详见 `D:/Webstock/output/diagnostics/collection-transcript-audit-20260926.md`。该报告中的数量是当时的核对结果，执行前必须重新生成清单。

## 拟议决定

1. **保留当前生产数据库为权威库，固定唯一数据根。** 本轮不另搬整库到一个新目录，不合并旧数据库。更新 EXE 不再隐式改变已有部署的数据根；新安装和明确的独立便携运行仍允许拥有独立数据目录。后台初始化和队列恢复前取得绑定真实数据根的系统级单写入锁，不将进程隔离误认为多实例防重。冲突或目录不可达时报错，不悄悄创建空库替代。
2. **恢复是有清单的迁移，不是开放任意路径。** 对旧文件的作品身份、文件类型、大小、哈希和所属目录核验后复制到当前归档根，验证后再更新引用。迁移/回退均核对预期引用及相关记录版本，遇新补采/修订结果不覆盖。原文件保留，同名异哈希进入冲突清单。已有 Python 可经验证后重新关联；模型归入固定模型目录。空间不足则停止，不自动删除旧文件或放开跨根访问。
3. **远程采集与本地处理分开执行。** 发现、详情和下载遵守登录/身份/平台限制；已有可信本地资产的 ASR/OCR 不依赖平台登录。复用现有后台进程、任务队列及运行明细，不增加另一套服务或图数据库。
4. **一份文稿状态解释供所有模块使用。** 保留原始 ASR/OCR 证据，分别表达提取完整性、机器质量、人工复核、分析进度。机器合格不叫人工核验，作者观点不叫企业事实。无严重异常的机器稿可自动进入候选观点分析，严重异常必须阻断并解释。
5. **版本与任务身份由材料决定。** 作品身份、媒体/正文哈希、处理规则版本确定任务输入；成功记录不因重启或刷新重复处理。模型升级需要明确的重处理意图，不因界面选择变化自动全量重转。失败、重试和人工修订均保留历史。
6. **旧分析恢复为历史分析。** 已找到的 42 篇/100 条关系不得丢弃，也不得伪造新版规范版本；按原始来源、正文哈希及引用校验恢复历史视图，新版提取结果另存。

## 未采用的办法

- 直接重新全量采集：不能修复旧媒体路径、缺环境、错误状态字段，会重复下载并增加平台请求。
- 只修登录：本地处理和产业链状态仍断链。
- 把 `needs_review` 全改成 `complete`：掩盖提示词回声、缺页等真实质量风险。
- 放开文件访问根：绕过安全边界，且仍不能保证读到正确作品。
- 更换数据库或重写整个应用：当前证据不足以支持，扩大风险，不是本轮必要条件。

## 后果与约束

- 迁移须备份、预演、可中断续做、可回滚；应用写入协调在实施时另行确认，不能趁运行时直接覆盖数据库。
- 全量历史可用性需逐项清单，不保证平台不可访问的作品也能取到；不可用必须有原因。
- AI 接口尚未配置时，仍可恢复媒体、转写/OCR、查看文稿和旧分析；新关系提取等待配置或合法外部结果导入。
- 用户只需处理真实登录/验证码、AI授权选择及无法自动解决的复核项；不要求每篇都人工点通过。
- 延续 ADR-004 的主进程/后台隔离，文件复制、哈希和模型推理不回到窗口主线程。
