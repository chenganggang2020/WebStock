# ADR-004：隔离桌面窗口主线程与数据服务

日期：2026-09-22。状态：已实现，106 项针对性测试、真实 Electron 隔离窗口检查和便携包启动检查通过；19:23 用户确认退出后已切换实际运行实例，原数据与旧版保留。长期稳定性尚未完成验证。

背景：真实运行日志反复记录作者资料读写、本地秒级查询期间主线程停顿，健康与静态接口同时超时。同步 SQLite 及后台调度与 Electron 窗口管理共用一个线程，定时自动采集不能提供响应性隔离。

决定：窗口、托盘和持久登录会话保留在 Electron 主进程；Express、数据库与业务调度移动到同一独立 Node 子进程。使用现有 Electron 运行时和私有 IPC，不增加依赖。保持数据目录、外部 API 和自动任务频率不变。作者采集通过有限的原生页面方法桥接，批次保存回调仍等待完成；断连不重放写入。

未采用：逐条把 SQLite 调用改成异步会破坏已有同步事务和大量服务契约；只增加 timer 或 Promise 无法隔离同步阻塞；每个任务一个数据库进程会增加写竞争和重复调度。

后果：后台自身仍可能繁忙，接口慢与窗口无响应将分离；界面缓存策略和数据库性能优化仍需独立实测。桌面/后台观察器分别写入 diagnostics/runtime.jsonl 与 diagnostics/backend/runtime.jsonl。启动失败必须关闭已打开资源；正常退出等待后台，不强杀或自动重启采集。

验收与范围见 ../development/Desktop_Backend_Isolation_20260922.md。
